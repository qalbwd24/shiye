# Android 023 跨端 UI 契约与独立审批门槛

2026-10-19。用户明确要求在开发前规定跨端行为和审批标准，独立子代理审批，避免细节漏验。本文件先于023跨端壁纸/共享设置/媒体任务合包生效；已确认的局部输入、候选栏、动画可独立实现，不把局部实现当跨端完成。原始需求见[21项手机反馈](ANDROID-023-CHAT-EXTERNAL-FEEDBACK.md)。

## 已确认的产品行为

- 会话及消息跨端共用同一服务器、资料库、稳定会话ID/消息ID与引用；媒体原件同一资源身份。各端触控、窗口布局按自身尺寸实现。当前两端分开调试且尚未互通，不能以候选数据口存在宣称互通。
- 会话壁纸图片默认跨端同步，可按每个会话关闭同步，其他会话仍默认同步。关闭后以desktop/android稳定端范围分别在服务器资料保存独立图片，支持换机/重装分别恢复；重新开启使用原共享图片，并保留各端独立图片便于以后切回，不用当前端图片自动覆盖共享图。用户已明确手机默认cover：保持原比例铺满手机屏幕、适当裁剪；位置、缩放、遮罩/透明度按设备单独保存。不能把手机裁剪后的缩略图上传覆盖共同原件，也不能把电脑绝对路径/blob URL当共享身份。
- 共享壁纸原件/会话绑定需服务器稳定asset引用及版本化写口。具体字段和端点由后端确认，未定前不写另一份本地权威绑定；上传ACK前保留已选草稿，绑定ACK后才标保存成功。其它端暂缺原件时显示可恢复状态，不把旧背景静默写回覆盖。
- 设备显示参数用稳定会话身份+本机设备范围隔离；手机/电脑分别调整不互相覆盖。随键盘变化使用稳定页面视口，IME不重新裁切壁纸；原件可重开/离线复用与回收遵循媒体契约。
- 图文消息沿现有text+attachments/units结构作为同一业务消息完整渲染，图片可点开；多媒体逐项保留ID/顺序/原件。允许多个视觉块，但不为了布局拆成新的业务消息ID，不改引用/评论/撤回/归篇。若旧格式实证无法保留，再给具体方案向用户确认。
- 本人撤回重新编辑参照电脑ui48：旧正文只本机持久恢复，无限期；确认编辑后原条无正文提示、原时原位后继，保留引用/评论对象与稳定operationId。未知owner不自动迁移或假写成功。
- 归篇间隔是`idleHours`（无新消息截断，默认5小时），不是朝花夕拾回看`interval`。会话资料、程序实例参数、设备外观、消息归篇各自按已有owner写，程序参与不能只保存servicePlan文本冒充已绑定。
- 大文件独立上传须有持久逐任务状态、稳定身份、进度/失败恢复，不锁其它文字发送。本轮后端已明确现有uploadFiles未实现完整后台job，不能把临时Promise或进度动画当恢复队列。
- 用户确认现有消息16/输入25调整为16/14；紧凑单行、多行增高、字号独立可调。迁移仅在新候选按明确版本完成一次，只改实际旧16/25组合为16/14，不改其它自定义字号，保留其它偏好/未知字段；不直接改当前手机。

## 独立审批标准

根负责整合与提供证据；实现代理不能审批自己的改动。用户最新明确：Astra只规划，Sol负责代码、测试、修复等执行，覆盖此前Astra负责视觉或难度代码的分工。独立`sol_completion_review`（Sol高）只读需求、契约、冻结源码/包、真实回执并独立给出“通过/有范围限制通过/拒绝”。审查结果写入产物，不以根口头声明替代。

| 门槛 | 通过所需证据 | 必须拒绝或保持未完成的情况 |
|---|---|---|
| G1 需求冻结 | 用户已确认行为逐项编号；未定字段/视觉含义明确待定 | 擅自替用户选择消息拆分、壁纸同步范围、清草稿时机；漏手机反馈 |
| G2 跨端身份/owner | 真实端点与能力、稳定ID、版本/CAS、原件SHA；两调用端读写同一业务实体 | 假控件/只改缓存；两套同名会话；自动切库；caption/附件/引用丢失 |
| G3 壁纸 | 同一asset跨端可取、手机cover且比例不变、各端参数独立、键盘不重新裁切 | 写本机路径作共享值、覆盖原件、位置参数串端、失败却显示保存成功 |
| G4 草稿/发送/撤回 | ACK/失败/重试和迟到响应、切房/新输入保护；恢复正文只本机 | 未保存清稿、迟到清新稿、重试新ID重复发送、旧正文上传、错房错引用 |
| G5 手机交互 | 目标1264×2800/density632/font1.3；关键真实Android触摸/IME/长按/搜索返回；必要MagicOS路径明确 | 只用DOM代替OEM ActionMode/系统长截图；选菜单文字、键盘意外收起、触滑改参数 |
| G6 动效 | 单发/连发/ACK/历史/返回的实际帧与节点身份；非线性过渡且无中间空白 | 用rAF当物理FPS、全屏透明遮空帧、ACK重挂/重复；只称“看起来应该好” |
| G7 媒体队列 | 大媒体任务持久/进度/失败恢复、普通文字并行、原件/消息稳定身份 | 只有发送中动画、整个房被大文件锁、失败丢附件、全文件巨内存读取冒充流式 |
| G8 冻结与交付 | 白名单/依赖/候选SHA、同源QA包、实际安装身份；源码/隔离/安装/启用分开 | 混入并行未验候选、用旧包回执冒充新包、未装手机却称手机已修完 |
| G9 打开与渲染性能 | Astra仅提供规划/算法方案，Sol执行复现并测量壁纸读取/解码/首绘、页面挂载、消息节点复用；实际打开会话/编辑页的关键帧与主线程耗时，冷/热状态分别标注 | 主线程大图同步解码、无界缓存/重复全页重建、只加长动画掩卡顿、把并发测量当空载或rAF当物理FPS；效果不达标须继续查官方/成熟开源方案 |

按影响选择核心复验，不机械跑全库。受同一根因影响的最少真实场景优先；未改功能按冻结源码hash复用。一次定向失败先定位，保留失败及修复范围，不能删失败凑通过数量。存在未知门槛时可以交付明确局部候选，相关需求保持未完成，不能批准整项正式启用。

最新用户确认独立图片也须随服务器资料保留并在换机/重装恢复，旧仅本机独立图提案失效。后端现已提供独立数据层冻结候选及[壁纸](SHARED-CONVERSATION-WALLPAPER-V1.md)/[媒体任务](SHARED-UPLOAD-JOBS-V1.md)契约；前端G2/G3/G7尚未接线及独立端到端验收，不能因数据层通过放行整个UI。初版独立Sol高预审仅限局部候选；每会话开关、重新同步保留覆盖图均须按最新契约核。UI022 QA12是独立前序范围，不自动批准023。
