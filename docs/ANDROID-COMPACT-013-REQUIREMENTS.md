# Android 0.13：真机反馈后的界面密度修正

2026-10-18用户手测手机0.11后提供两张截图。现有UI整体过大，不能把此前AVD“无溢出”或最小字号可选当作满足视觉密度。手机继续用户手测；本轮先在匹配320dp的电脑AVD核查，未经后续请求不再覆盖手机。

## 用户确认

- 正文/输入/时间字号的可调最小值远不够小，需要继续下探；按钮、图标和输入栏高度一起缩小，不能只改消息正文。
- 消息气泡尽量减小上下留白，短消息不应因时间再多占一整行。时间戳明显更小，放在正文末尾右侧，自动给尾部留位置；多行/临界换行/引用不能遮挡正文或越出气泡。
- 本人消息靠右，去掉气泡整体宽度限制在整行上造成的多余右侧空隙。消息之间仅留小空隙，仍可调。
- 附件、表情、发送按钮风格和尺寸一致；表情包缩略显示需适配，小图/GIF不能撑满屏。
- 已收藏表情包点击直接发送，不再弹图片发送确认，与电脑客户端一致；普通文件/图片选择的原有确认不因此一并跳过，原图/GIF字节和真实本地ACK保持。
- 深色目前稍过黑，维持冷蓝色但适当提亮，并保留壁纸与既有用户自定义参数。

## 核查与实现方向

同轮后续确认：长日记编辑页的分类新增/删除/默认/拖动排序集中单页，分类多时支持页面滚动与拖动边缘滚动；成功自动保存不再反复闪“保存于”，错误仍提示/可重试；字数固定在工具栏上方左侧，键盘弹出也稳定；空白正文留足可下滑空间但不插入空段制造数据。用户称“随想编辑”，此处按截图中日记分类/字数/保存时间/写作工具栏判定为思绪长文编辑，随想仍按消息页处理。

全局外观澄清：深浅模式要覆盖全软件，改变前景黑/白和透明浅/深色调层，不能只聊天生效、也不能实心底色盖壁纸。参照电脑`public/features/appearance.js`和`public/styles/appearance.css`，背景/主题分层、文字自身不降低透明度。全局主题集中于应用设置；思绪列表、写作页、随想列表、聊天默认及当前会话壁纸分别管理，不互相覆盖；旧独立theme字段保留历史但渲染服从全局。设置层级与返回要清楚。

后续用户明确否定思绪“一块一块”的大卡片：一本日记参考是连续的正文摘要、下方小字日期/时间/分类等和细分割线，不是每篇大圆角底板。取消普通记录和月份/置顶标题的大底板，置顶只保留轻微平面色调/标识；壁纸/全局主题继续保留，不能为透明主题又叠回大色块。此需求优先于本轮初次卡片实现。

当前原生思绪列表确实只有纯色背景，旧思绪写作壁纸并不等于列表壁纸已完成。本轮补独立list作用域，而非把旧写作壁纸搬走。随想列表已有listBackground字段/接缝，本轮要重新验证实际渲染，不把字段存在当作图片选择/保存/重开全流程已验。

手机仅只读获取计算样式（未读消息正文或操作输入）：宽320/DPR3.95，HTML/body字体20.8px、text-size-adjust100%。当时不在消息房，未取得消息/输入区节点，不能把空数组当成消息渲染已验。旧读脚本严格比较含hash的完整URL未找到页，后改按origin/path匹配；自己的临时ADB forward已清除。

拟为聊天与思绪WebView显式设置textZoom100，应用内字号不额外叠加系统font_scale1.3；必须以真实AVD最终计算值验证，不能只推断setter一定修好。系统输入法/全局手机字体不改。正文/输入范围向6px下探、时间向5px下探；新紧凑推荐正文13/输入13/时间8，横padding8/纵4、间距3、宽度90%。具体最终值依实际渲染核验，旧自定义值保留、推荐设置保存后才生效。

CSS不只限定含`.shiye-markdown`的消息，需覆盖实际普通文本metadata；短文本、英文、长中文、多段、引用、纯emoji、媒体/GIF、不同字号与320dp宽度均检查。时间流内排列与尾部占位不能以绝对定位盖正文，也不以整页transform/zoom假缩小。引用/撤回、原件/块/出现身份、未发送草稿、IME组词和本地优先保存保持。

0.12原生服务连接成果保留；后端内容/服务适配继续按[实际内容契约](DESKTOP-ANDROID-CONTENT-CONTRACT.md)、[服务接入](ANDROID-SERVER-CONNECTION-012.md)推进。UI修改不改正式电脑库/规则，完整Repository/outbox、绑定/自动收件仍待接，不能通过渲染修复冒充数据同步完成。
