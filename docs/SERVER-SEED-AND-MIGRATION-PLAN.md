## 手机离线种子接入门槛

1. 包用统一新版记录、稳定ID、媒体索引/原件及manifest。包含实际可同步的会话/分类/标签/资料与表情包名称/备注/分组；电脑会话用图可用于安卓头像，不能因导入素材自动覆盖安卓本机壁纸。范围按[共享与本机展示](SYNC-DATA-SCOPES.md)；本机窗口位置、绝对路径、认证密钥不进通用业务包。
2. 私有staging检查版本、清单hash/每件hash、安全路径、库身份与对象引用，再事务导入；大文件使用文件流，支持中断续跑和重复导入幂等。旧本地资料和未知字段保留，不直接覆盖手机SQLite文件。
3. manifest若带libraryId/epoch/快照游标，必须来自同一服务的一致快照；联网校验同库后接续增量。不能把任意JSON导出时间冒充服务cursor，也不能导入别人的配对密钥。
4. 手机已有未同步写入时保持outbox并按既有冲突策略合并；包内记录不重新变成手机新增消息。导入媒体按assetId/hash复用，并原子发布验证完成文件。
5. 先小合成包测试中断、坏hash、重复、异库及本机未发队列，再少量真实数据；全部完成才声明本地离线资料完整。该入口由Android会话按后端包规范接入，不改日常窗口。

本次电脑用`shiye-bundle`承载原ZIP、legacy追溯和canonical消息，只是既有正式恢复API的迁移容器，**不是未来仅新版的手机种子规范**。

2026-10-18用户确认：以后同步不再需要旧格式，仅以统一新版结构传输；Android完成后先少量测试；电脑可以把初始文件发到服务器，由服务器AI解包接入后端；手机无需手动解压分类或搬壁纸。本文为后续实施要求，不是已经交付的导入API/云部署。

## 数据格式约束

- 原始一本日记导出、旧diary.json和备份继续保留，作为只读导入、核对与回退来源，不放进日常同步清单。
- 历史资料在独立转换副本中生成统一图文/消息结构：正文、稳定单元ID、布局、时间依据、媒体出现、分类/会话/引用/评论关联完整。原HTML的保真读取层仍可用于核对，不能只给它套_product外壳就宣称完成新版转换。
- 本轮既有sync-product是兼容后端，仍接受部分旧Entry字段。正式“仅新版”的导出清单/校验门槛与能力标记**尚待实现**；不因这条新要求直接删现有保存字段或改正式canonical开关。
- 新版消息仍可有Markdown文字内容；“不用旧格式”不等于删除Markdown格式或丢失代码/换行。以标准业务结构/身份为准，兼容缓存与原件的传输范围由新版导出规范显式定义。

## 两类搬运，不混淆

| 场景             | 方法                                                             | 手机动作                           |
| ---------------- | ---------------------------------------------------------------- | ---------------------------------- |
| 云端初次资料预置 | 上传新版记录/媒体原件/校验清单，服务器脚本校验并导入独立目标     | 配对后经API自动初始化，不解包      |
| 日常同步         | 独立实体变更流＋按hash验证的资源传输；断线续传                   | 自动本地事务、队列、渲染及后台下载 |
| 已用服务整体搬家 | 一致快照迁移服务数据库/身份/游标签名/回执/认证及媒体，随后换地址 | 核对同一库身份后继续原游标         |

已有服务不能仅上传几份records JSON就称为完整搬家；否则设备身份/epoch/游标/幂等回执可能不连续。初次新库种子和已配对服务迁移必须在manifest声明不同模式。私有认证/签名材料不写进通用业务样本或公开日志。

## 建议包结构（候选）

早期目录建议（实际已采用`.syseed`流式容器，Android不要按此另做ZIP）：

```text
manifest.json             格式版本、模式、库身份、记录/原件计数及兼容能力
records/*.ndjson          统一新版结构；按主体稳定ID，不是一篇篇AI改写文本
media-index.ndjson        assetId、内容hash、大小、MIME与必要原件映射
media/<sha256>            图片/视频/GIF/头像/壁纸等原件字节
checksums.sha256          包成员校验
```

媒体通常已经压缩，打包不重新压缩/降低画质；仅合并传输与校验。会话的壁纸/头像使用关系、透明度、分类标签和排序等作为records对象，图片字节作为media。缩略图可重建；完整离线原件仍须最终补齐，不将缓存当原件。

## 服务器AI的职责

AI运行版本化、可重复执行的工具：检查包与目标身份→安全解包→校验版本/hash/引用/单位与时间→dry-run导入报告→独立库导入→比对数量/媒体→接入后端。保留原包和可回退快照，拒绝路径越界、缺件、身份冲突和异常格式；错误单独报告。AI负责执行和诊断，不逐篇理解重写日记或自行决定冲突正文。

当前未提供服务器地址/凭据，未上传个人资料、未部署云端，也未把候选包格式当成可用工具。正式实施前补齐导出/导入幂等脚本、只接受新版的能力协商及一致快照流程，再做小批量闭环。

## 测试与手机接入顺序

1. Android先完成既定Repository/事务/网络接线；小批合成测试覆盖文字、图文时间、媒体原件、会话壁纸/头像、分类/排序、引用/撤回、收件/评论与断线恢复。
2. 手机一本日记导出后，先只读去重、独立转换、异常复核，不覆盖旧资料；实际新格式大小由导出manifest测量。
3. 少量经复核的真实资料只在隔离库验写入、渲染、原件及往返；满足门槛后再正式同步和云端预置。
4. 手机自动消费结构与资源编号，优先恢复正文/会话身份及表情包名称等业务数据，后台补媒体；已有安卓壁纸保持，不自动套用电脑壁纸。不要求用户在手机文件管理器操作解压或分类。
