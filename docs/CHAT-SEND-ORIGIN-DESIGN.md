## 已复现的问题

安装ui21、496×942 CSS px、DPR1.75，满屏、64px手调输入框、平滑单行：约156ms停稳，约622ms上游bottomInset由64变88，实际padding由80变88，约631ms消息再次上移8px。footer和包装reserve一直为80。原因是上游发送收缩锁600ms后恢复额外8px间距，与包装层即时留白不一致。仅统一CSS到footer reserve+8的隔离A/B已消除二次位移；最终实现还统一上游预测，覆盖取消、选择模式等边界。

证据：`outputs/2026-10-17-send-settle/smooth-min-496-dpr175`及`ab-A-smooth-manual64`、`ab-B-smooth-manual64`。这些是合成库证据，不含真实消息。

## 核心实现约束

- 有效活动footer绑定时设置`data-shiye-footer-layout="managed"`，原始reserve为实际footer高度向上取整；有效消息留白统一为该值加8 CSS px。切房解除旧绑定，无footer/选择模式保留上游专用逻辑。上游managed路径不再建立600ms收缩锁。
- 新smooth模式复用即时布局提交，然后仅新气泡做160–220ms的transform/opacity过渡。发送前读取输入文字可视区域与光标锚点，不固定从屏幕底部起飞。不延后数据提交。
- 动画期间clip消息容器，避免视觉变换撑大scrollHeight；旧消息不做反向FLIP。ui13曾出现DOM轨迹正常但实际合成画面先跳再回落，不能重用该旧方案。
- 本地确认换ID/节点时继承同一动画时钟，不重播；滚轮、切房、隐藏、减少动画、设置改变时清理。发送操作没有动画等待门槛。
- 同一Message只换content也必须接续动画；同批多附件共用本次发送锚点。活动列表只绑定同父footer，不能在切房双可见阶段全局误选旧输入区。
- 空会话首条消息由新气泡独立过渡，上游NoMessages→MessageList不再整组淡入。逐帧截图发现额外淡入遮住来源起点后才补此项；此最终补丁需要重新构建验收。
- 设置保留instant（即时）、smooth（从输入框发出）、legacy（原平滑）。现有即时偏好保持；原smooth选择升级为新来源动画。
