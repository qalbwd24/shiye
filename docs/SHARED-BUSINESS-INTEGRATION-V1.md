`GET /api/shared/v1/info`；`POST snapshot/pull/command`。command 固定 `{libraryId,epoch,operationId,action,input}`，不可变 wire 重试使用同一 operationId，同 ID 异值 409。业务冲突保留草稿/outbox，不自动覆盖。ACK 是最小身份回执，客户端拉取权威数据后再移除队首。程序设置复用原子多 slot 接口。

## 原件、大正文和恢复

`POST media/begin|chunk|complete|read` 属于同一鉴权命名空间，单块不超过256KiB，原件保留原 JSON media 身份，单件上限16GiB。分块大小、SHA、偏移、重复ACK及最终SHA均核验。旧去重原件缺失/损坏时明确409并保留新正确字节，不丢掉唯一有效文件。默认浏览器展示 sink 限64MiB，较大文件需持久流式sink；未进行16GiB压力或Magic7内存验收。

snapshot/pull 页面约1MiB以内；大实体返回显式 descriptor，再通过 `POST entity/read` 读取完整UTF8 JSON，SHA/身份/版本全部验证后才整页提交。64MiB是完整单实体payload上限，Entry正文/文档各字段仍沿用原业务限制。大日记保存将 Blob、不可变小ref命令与乐观副本同事务保存；重开后分块上传，再由 `entry-create-ref|entry-save-ref` 在原 Entry 路由校验保存，不把大正文塞进4MiB原生request。服务端通过同库上传回执解析真实assetId，去重不改已冻结wire。

读页并发变化不永久暂停；过期游标单次同步最多重新快照一次，保留草稿/Blob/outbox。确定拒绝暂停重发。`client.reconcileBlocked({operationId,mode:'retry-unchanged'|'discard'})` 是显式审阅口：409须先准备新版本/新operation；discard保存完整本机恢复件，不冒充ACK。未知ACK或已ACK后读取失败的命令禁止discard，继续原wire确认。
