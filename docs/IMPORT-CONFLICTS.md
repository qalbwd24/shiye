# 导入重复与冲突规则

代码：后端 domain/import-reconciliation.mjs，routes/conflicts.mjs；前端 features/conflicts.js。

## 身份和内容分别判断

日记先匹配自身 ID、restoredFrom.id 或 legacy.original.uuid。没有同标识候选时再找非空的同标题候选。空标题不能把所有无标题日记配成冲突。相同标题但不同日期仍保留两篇，不自动删除。

自动合并要求当前正文、日期、分类、标签、状态、附件（映射后的媒体ID）、历史、未识别旧字段等比较结果一致。标签顺序不影响判定；同步标志、导入产生的新ID、更新时间等技术字段不当作正文差异。历史/未知字段不同也保留供核对，宁可提示差异而不静默丢失信息。原始加密备份仍保留。

媒体采用 SHA-256 + 大小 + MIME + 用途判断相同文件。相同文件只保留一份工作库媒体记录及实体文件，不重复占用附件位置。名称不同不影响字节去重；名称相同但哈希不同创建媒体冲突。背景与日记附件分别按用途复用。旧媒体缺少哈希时在启动阶段流式补齐。

## 人工决策

- 保留两份：保持两份，可给导入版本改名，记录决策。
- 采用某篇日记：另一篇移入回收站；不物理删除，可从回收站恢复。
- 采用某个媒体：当前日记引用改指向选中的版本；旧文件、旧历史仍保留，可在单篇历史恢复旧附件关系。
- 日记决策必须带两边 revision；期间任一篇被修改则拒绝，要求重新比较。
- 已处理记录可查看，不提供一键反向重放，因为处理后的日记可能又发生编辑。

## 接入范围与限制

旧 ZIP/JSON/Windows 数据导入、syvault 和 syvault2 恢复、普通媒体上传已接入。相同备份原件的再次直接导入仍提示“已导入”，不会重复处理。恢复加密备份允许再次校验，然后跳过完全相同条目。

数据库的 conflicts 数组记录 kind、left、right、reason、status、choice 及时间。syvault 和 syvault2 保全已有冲突记录并重映射关联 ID；被判为完全相同而合并的同一对象不再产生双份冲突。

这不是网络同步引擎：没有连接官方服务器、网盘或 WebDAV。未来同步需增加远端版本/删除标记/设备来源/中断续传协议，复用当前判定与人工处理模块。不能对明文 diary.json 使用普通文件同步并让多个运行中的服务同时写入。

当前不会扫描并自动清除升级前已存在的重复条目。精确相同的新增工作媒体会删除新写入的冗余副本；不同内容的媒体和原始加密包不会为了省空间而物理清除。备份原件保留会占据归档空间。
