# 0.6 功能分层与迁移核对

更新：2026-09-22。结论：**还没有完整复现 Android 1.96.55 的所有离线行为，也没有接通官方云；电脑端已经接入自有 WebDAV 的安卓格式合并同步，但服务器部署和手机真机往返仍待验收。** 原始字段保留、功能入口存在、实际使用验收，是三个不同状态。本表是当前统一进度入口；早期报告只作历史依据。

## 本轮需求与顺序

1. 保持现有页面风格，先保证日记功能、数据兼容和模块边界。
2. 文本编辑核心以后参考 Obsidian/CodeMirror 改进；本轮不替换编辑引擎。
3. 分类标签有独立管理页，可搜索、创建、改名、合并、移除，选择排序并同步左侧导航。
4. 媒体拖入有明确落区、队列、上传与保存进度、单项重试；重复文件复用。
5. 旧备份或加密备份重复导入时识别相同内容和冲突，提供对比、改名、保留两份、二选一及处理记录。
6. 后续再细化字体、字号、背景对比度、模板体验及层级布局；暂不增加复杂装饰。

## 发现并修补的数据兼容问题

- 旧 Markdown 只转换显示，没有接上回编源码：新导入同时存源码，旧记录只在正文仍与原转换完全一致时补齐源码，不覆盖修改过的正文。
- 旧隐藏状态仅在 legacy 中：后端保存现有记录时保留原隐藏状态；升级补齐缺失显式状态，并提高 revision 拦住旧窗口覆盖。
- Android 心情实际用 m 字段：根据本地原代码 o4/h.java 的 p(int) 映射中文，不把它当成空心情。
- 原模板 isDelete 状态此前丢失：新导入保留；升级仅处理内容、名称可核对的未编辑模板。
- 小文件旧导入入口此前漏接模板和独立标签表，现与大文件入口保持一致。

升级先复制工作库快照，再通过串行存储补齐可确定的字段。日期、正文、分类、标签、旧 original、媒体字节不重写。没有逐篇审阅用户正文，不以此宣称所有排版正确。

## 开源设计参考与复用方式

- [Uppy Dashboard](https://uppy.io/docs/dashboard/)：参考常驻队列、每个文件的进度、失败状态及重试入口。
- [dnd-kit 可访问性](https://dndkit.com/legacy/guides/accessibility/)：排序需要键盘替代，不能仅支持鼠标拖拽；本轮先提供 ↑/↓ 按钮。
- [Joplin 冲突说明](https://joplinapp.org/help/apps/conflict/)：保留冲突副本，交给用户比较和选择。
- [Syncthing 同步机制](https://docs.syncthing.net/users/syncing.html)：同名差异不能靠更新时间猜测用户想保留哪一份。
- [Obsidian 编辑器扩展](https://docs.obsidian.md/Plugins/Editor/Decorations)：编辑引擎、状态与扩展分层，供下一轮编辑器方案选型。

本轮复用交互设计方法和本项目已有模块，没有引入上述项目的运行时代码，也未直接复制源文件。仍为离线原生 ES 模块；下一次引入具体第三方依赖需固定版本、保留许可证，并明确适配层。
