## 用户已确认的方向

- 便签接近Notepads：自由书写、长期修改、自动保存，不自动插入正文时间戳，不参与朝花夕拾。
- 最终希望在软件书写便签、待办、日程，并自动投射桌面，支持AI/程序处理；当前讨论完整能力，不按首版/次版限定。
- 新增习惯打卡需求。
- 考虑手机、电脑、手表及某种互联设备/中枢互通，具体平台和连接方式未定。
- 这些生活管理数据不强制套用日记的数据格式；待办、日程、习惯等详细结构尚未想好。
- 用户目前较少使用这些工具，希望逐步用来管理生活。交互应保留直接记录的低门槛，不以大量必填管理字段为前提。

## 推荐原则（AI建议）

**业务对象按用途独立，通用基础能力按需复用。** 日记与聊天继续已确认的统一消息方向；其他模块不必改造成日记消息。独立类型不强制要求同一个JSON、同一个数据库或同一种正文；实际存储可按模块分表/分文件，物理选型后定。

| 类型      | 核心对象                       | 时间与修改语义                                                       |
| --------- | ------------------------------ | -------------------------------------------------------------------- |
| 日记/聊天 | 已确认的内容单元、篇与会话归属 | 日记完整手打锚点/媒体插入时间；聊天发送时刻及撤回新号重发            |
| 便签      | 可长期修改的独立文档           | 正文无自动时间；内部创建/修改元数据服务于恢复/历史，持续更新同一文档 |
| 待办      | 一件要完成的事项，可有子步骤   | 完成状态为核心，截止/提醒为可选；修改原事项                          |
| 日程      | 某段时间发生的安排             | 开始/结束、时区等业务时间，提醒/重复可选                             |
| 习惯      | 一项重复行为的定义/规则        | 例如按日/周目标，具体规则后定                                        |
| 打卡      | 对某个习惯的一次完成记录       | 关联习惯ID、发生时刻、归属日期，补记/撤销/次数等规则另定             |

习惯定义与每次打卡记录分开，次数/连续天数可从记录计算。不能只存当前勾选或一个连续天数，否则后续多端合并、补记、撤销及改规则都难解释。一天一次还是多次由习惯规则决定，不因两个设备同一天操作就一律合并为一次。

图文便签可直接复用现有richdoc和媒体身份；任务/日程/打卡以自己的业务字段工作，说明正文或附件有需要再接。共享图文能力不要求打卡也包装为富文本或带“发送时间”的消息。

## 关系而非重复正文

便签某个条目可以关联任务，任务可以关联日程或提醒，习惯可以关联打卡记录；每个对象保持稳定ID与单一权威状态。桌面和各设备展示这些对象的投影，不各自维护一套正式任务状态。

AI/程序通过明确业务操作读取、创建或修改对应对象，保留来源/版本。日记可按需引用它们，但便签已明确不进入朝花夕拾，其他模块也不因“共享接口”而自动成为日记回忆来源。提醒投递到聊天的消息可关联原对象，原对象仍由自身模块管理。

## 多端真正需要共用的部分

跨端互通主要需要共同的同步外层和业务操作，未必要统一所有业务正文：

- 对象类型/稳定ID、schema版本、内容修订与删除状态。
- 每次写入的操作ID/来源设备，支持离线后重试与防重复。
- 媒体资源ID/字节传输；本机路径或浏览器Blob地址不能直接成为跨设备地址。
- 不同对象各自的冲突规则：便签正文冲突保留分支，待办状态用版本操作合并，打卡按事件身份去重；不能只比较设备当前时间并覆盖。
- 业务时间与服务器接收时间分开。日程时区、打卡归属哪一天及补记时间需要明确；便签内部修改时间不成为日记时间锚点。

电脑、手机、手表应通过共同数据服务/同步协议访问；桌面组件是一个显示入口。手表可以有适合屏幕的轻交互（打卡、完成、看提醒）与手机/中枢交换操作，具体能力取决于后续选定的平台，不在本轮承诺原生支持或选定厂商互联方案。

可以讨论由自有服务器、常开设备或手机充当同步中枢，设备直连/转发等方案后续结合实际设备确定。本轮不要求部署服务器，也不假设所有设备必须同时在线。

窗口位置/折叠/光标/本机桌面布局与业务数据分开；哪些偏好跨端共享另定，不能把电脑窗口坐标直接当作手表界面状态。

## 已有实现与边界

- 日记/聊天统一数据仍是隔离候选，旧日记副本及复核结果不回写原库。
- 便签当前是独立前端及IndexedDB快照，未接正式事务数据接口；界面会话继续其工作，本讨论不改UI或profile。
- 现有WebDAV同步为兼容一本日记的日记/媒体协议，见SYNC.md；它不是通用便签/待办/习惯/手表同步协议，不能直接据此宣称上述多端能力已有。
- 现有开放日记读取接口不等于个人事务同步协议，尚无习惯、打卡或通用任务写接口。
