## 推荐迁移顺序

1. 手机原版先导出“完整备份”，勾选媒体；只导入一次到桌面端，并核对日记、媒体和分类数量。
2. 在桌面端先执行“测试连接”，确认 WebDAV 地址、认证和 `diary/` 目录可用。
3. 云端为空时执行“合并并同步”，桌面库成为第一份云端数据；手机端之后读取同一份 `diary/diary.json`。
4. 后续由桌面端或手机端各自先拉取再写回。桌面端会按稳定标识合并；发现同一标识内容不同会暂停上传，等待冲突管理。

## 流量边界

- 首次迁移：上行约为 `diary.json` 大小加尚未存在的媒体总大小。
- 只改文字：原版兼容格式仍需上行新的完整 `diary.json`；桌面端会跳过未变化媒体。
- 只新增媒体：上行新增媒体字节和新的 `diary.json`；已有媒体不重复上传。
- 完全没有变化：强 ETag 可用时，条件 GET 返回 304，桌面端跳过完整 JSON PUT，媒体也由指纹和 HEAD 检查跳过；正文有效载荷接近 0 字节，仅有请求头。
- 服务器不返回强 ETag 或不支持 HEAD 时，程序回退到安全路径，不把“同名”误判成“同内容”；这会增加请求或重复上传，但不会静默覆盖不同文件。
