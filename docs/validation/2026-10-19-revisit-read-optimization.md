# 朝花夕拾前端重复读取优化

用户要求先优化前端反复读取整个聊天库的问题，保留朝花夕拾接收、评论和撤回，再做定向测试及实际性能对照。本轮修改 `shiye-revisit-client.js` 的待发评论筛选、`shiye-revisit.js` 的客户端缓存版本，以及 `shiye-preview.js` 的页面修订标记；最终候选 ui40 基于已验证 ui39，原生、worker、journal 和 API 保持原字节或进程。

## 行为与并发边界

同步开始先处理原有撤回队列，再从当前快照筛选未确认评论，仅保留消息 ID。历史来信与已确认评论不再逐条读取整个库。每个实际待发评论发送前仍重新读取最新状态，重新核验消息存在、评论未确认、没有撤回待办，并使用最新正文和原固定评论目标。

仍保留从零分页重验历史来源、分页落地 ACK、草稿目标保护、媒体缓存以及失败重试。没有缓存整库以绕过并发检查，没有改变推送规则或游标。剩余每轮固定读取、逐页全来源解析和整库写入成本不在本补丁范围。

## 定向验证

- 17 项客户端测试通过，含 7 项新增用例；覆盖读取次数与历史条数脱钩、最新正文和固定目标、前一请求等待期间后续评论被撤回/删除/确认、撤回投递 ACK、评论失败后重试。既有实际后端＋ChatJournalBridge＋local worker 隔离联调通过。
- 27 项相邻评论/撤回测试通过，覆盖并发、去重、撤回墓碑、重启恢复及写盘失败。
- 8 项 Chrome 真 IndexedDB 对照检查通过，合成库含 8 MiB 媒体；前后顺序为旧/新/新/旧，各自独立 profile，不连接正式 API。两轮均确认普通 feed ACK 保持。
- 定向 ESLint 和修改文件格式检查通过。没有运行无关全量测试；原生/看图复用未改 EXE 和查看器资产的既有证据。
