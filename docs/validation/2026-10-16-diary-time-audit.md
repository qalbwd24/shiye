# 历史日记时间来源只读核对

本轮只通过正在运行的本机 `/api/library` 执行 GET。没有导入、迁移或保存正式日记，没有重启程序，也没有读取图片字节。报告只保存统计及来源摘要，不保存正文、标题、媒体文件名或逐篇身份。来源快照 SHA-256 见 `outputs/diary-time-audit/summary.json`；两次读取的摘要一致。

## 最新需求和实现边界

用户希望长文有明确手打时间时按它建立时间关联；没有时间戳时按日记编辑时间兜底，可考虑覆盖全部历史日记。先生成可重建的派生索引，不需要把原文重写一遍或自动插入可见时间。这是时间索引需求；旧数据仍不改写。

正文锚点、日记创建/修改和图片插入/拍摄/文件修改/入库时间应分别保留来源、精度及时区依据。未写时区的正文时间暂按北京进行本次统计，这是分析假设，不是已经确认全部历史文字都来自该时区。聊天归篇使用原消息 sentAt，不重复解析 HTML 投影来制造第二套消息时间。

无锚点时采用编辑时间为已确认目标；具体选择安卓原始 updateTime 还是后来实际修改产生的 updatedAt，需要保留来源并核对差异，不能隐式覆盖。只写时分、句中时间、有时间戳但之前存在正文的情况，仍需补规则；整篇级修改时间不能还原逐段写作时刻。

## 正式库实际覆盖

快照共 3013 篇，其中普通长文 3011 篇、聊天投影 2 篇。统计包含隐藏、删除、草稿及演示标记；这些标记可能重叠，不能把全部数量都当作用户可见的有效日记。未扫描 history 或 legacy.original 的历史正文。

## 安卓导出包是否有帮助

当前已经导入的备份格式使用 source.json 保存日记，原对象的 createTime、recordTime、updateTime 原样保存在 `entry.legacy.original`，并分别映射日记 date、createdAt、updatedAt。当前库已有这三组时间，用户暂时不必重新导出。

如果手机端有电脑未收到的新篇、更新或更完整附件，可另做一份安卓应用原生完整备份，保留原包；先只读比较，不能再次整包导入制造重复。不同导出版本仍需实际核对字段，不保证所有版本都有同一结构。导出文档/PDF并不能保证包含结构化编辑时间。已有原包代码支持明文/加密表识别，不需要用户手动解密或提供密码到聊天中。

## 图片时间

登记图片资源共 3046 个：38 个有 importedAt，28 个有有效 lastModified，0 个登记 sourceCapturedAtRaw，0 个登记独立 insertedAt；本轮长文 HTML 中也未发现带有效 `data-inserted-at` 的图片出现。未读取原始图像字节，**登记表没有 EXIF 字段不等于图片文件没有 EXIF**。

这些时间分别表示入库、文件修改或拍摄候选时间，不能证明某张图片何时插入某篇。旧备份里的图片文件/ZIP 文件时间即使可提取，也只能作为单独来源，不能直接升格为正文插入事实。旧图可随所属日记/段落的内容时间参与呈现，并明确这只是关联时间。

新富文本试验页在本地文件插入时会保存每次出现的 occurrenceId 和隐藏 UTC insertedAt；尚未接入正式快捷窗。旧图不自动补造 insertedAt。复制/移动路径的时间规则仍见继承基线，不按代码局部存在就宣称全部完成。
