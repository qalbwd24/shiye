# 统一消息与附件冲突处理一致性

本轮只修改数据层，并在隔离库验证。未操作桌面、未重启正式程序、未修改正式日记。

## 修改

- `src/server/routes/conflicts.mjs`：对图文长文替换附件及撤销替换时，在同一个存储事务中重建统一消息、正文顺序清单与 HTML 投影。保留消息 ID、媒体出现 ID、插入时间及评论目标。
- 同步受影响的评论媒体正文及其资源引用，评论出现身份保持，版本递增。评论同时含两份资源时拒绝合并，防止去重丢图。
- 聊天归篇的原消息只允许从聊天端撤回并重发；附件冲突操作及历史撤销均返回 409，不修改原消息。
- 名称与回收站修改保留原正文编辑时间；缺少该字段时只冻结有效的原 `updatedAt`。合法聊天标题改名同步兼容投影校验值，后续追加消息仍可进行。
- 批量中任一目标缓存不一致时事务整体回滚。

## 验证

`tests/message-unit-conflicts.test.mjs` 新增 8 项，包括图片、视频、评论、回滚、聊天只读边界、元数据时钟以及真实隔离 HTTP 保存／重开／撤销。

合并运行新测试及既有 `tests/data-conflicts.test.mjs`：16 项通过，0 失败。仅针对改动的两个源码／测试文件执行 ESLint 与 Prettier，通过。

独立 HTTP 测试只启动随机本地端口，数据位于 `tmp/message-unification/conflicts/<UUID>/`。测试文件均为合成文本和媒体，不引用真实日记。

未验证真实窗口的附件冲突交互；本轮用户明确要求只做数据层与隔离测试。
