# 2026-10-15 · 聊天自动归篇与拾页数据衔接

## 使用

每个对话右侧齿轮 → 拾页分类 → 自动归入拾页日记。新建对话默认启用，已有对话需要自行选择分类并打开。首次连接包含此前实际发出的消息，排除默认三个对话中 ID 1–10 的内置演示；其他测试消息不会猜测或删除。原先的独立聊天库保留。

消息先提交聊天 IndexedDB，再自动写入拾页正式库；连接失败不会阻止继续发消息。新发送触发补写，另每 20 秒检查一次。总设置 → 日记归档与保存状态可查看错误、立即重试或解锁本地访问锁。界面消息勾号表示本机聊天保存，归档结果在此状态页查看。

默认相邻消息间隔不足 5 小时接在同一篇；达到 5 小时另起篇，即使消息持续跨天也不会按日期强制拆分。服务每分钟结束已空闲的篇，重启时补检查；精确分篇依据实际消息时间，不依赖计时器准点或联网。日记从首条消息即存在，后续持续更新；结束不清空聊天。30 分钟居中时间提示仍是另一项显示设置。

日记时间和标题使用北京时间，消息 UTC 时间戳保留不平移。归篇时限从下一篇生效；改变分类从下一条消息另起篇，历史分类保留。归档日记在主窗口人工修改或删除后，后续自动另起篇，不覆盖或复活旧条目。原有普通长篇日记不改写。

## 数据和兼容

- 原始聊天数据仍在 var/telegram-chat-preview/webview；同 profile 的 shiye-journal-link-v1 保存稳定来源 UUID 与逐对话开关。未确认的消息继续留在聊天库，回执查询确认后才跳过，重启不依赖内存中的成功标记。
- 正式 diary.json 的可选顶层 chatJournal 保存配置；生成的 Entry.chatJournal 保存来源、对话、时限、状态、消息原文与正式媒体 ID。content 为安全 HTML 投影，普通主窗、搜索、统计可以读取。
- 图片、视频、文件走原生分块传输与原媒体入库逻辑，登记 SHA-256 并去重；不会再次压缩。普通文件按附件下载，避免作为网页执行。媒体进入原有备份清单，恢复会同时重映射嵌套消息附件。
- Markdown 显示保留标题、加粗、斜体、删除线、表格、任务、代码、引用和高亮；原始 HTML 作为文字，远程图片不抓取，危险链接不激活。
- 全部写入走原有 mutate 串行提交。重复同 ID 同正文返回同条目，改变已归档消息或乱序历史返回 409，保留本地内容并在归档状态显示问题。
- 原生只放行明确的本机日记操作，继承本地锁和请求来源保护，不放开页面或 Worker 的 Telegram 网络连接。普通验收模式禁止连接正式库；--verify --verify-journal 仅连隔离 18767。

## 本轮边界

聊天仍是本地优先的独立编辑入口，生成日记是归档视图。在主窗修改正文不会反向改聊天消息；聊天撤回／改写的双向同步、机器人、AI、定时回顾、手机和自建服务器同步不属于本轮已交付能力。跨设备协议与账号身份另议，不把 Telegram 协议对象写入正式库。

未配置自动归档的对话只保存到聊天库，不会进入普通日记备份。完整保留聊天外观、壁纸、草稿、表情别名还需要保留对应 WebView profile；当前普通备份不作为完整聊天应用恢复包。
