# 2026-10-15 聊天预览：入口与输入验收

范围：仅独立 Telegram Web A 本地预览；正式拾页仍为 0.9.17。本轮不迁移正式日记，不读取微信缓存，不启用 Telegram 服务、机器人、AI 或同步。

## 改动

- 左上角齿轮统一设置，放大镜检索消息文字，＋新建话题；移除底部浮条、重复话题工具条和原生服务菜单。Ctrl＋F 使用同一搜索。
- 本地表情面板和图片／GIF 收藏；导入后可确认发送。现有编辑器继续负责正文和选区；话题切换时按当前实际编辑器绑定，不依赖挂载时尚未就绪的 DOM ID。
- 可配置 `/` 命令：表情、表情包、图片、时间、搜索；支持中文名称、英文别名、↑↓／Enter／Esc，总开关和单项开关。机器人命令没有假接入。
- 背景改用独立 IndexedDB Blob，取消 3 MB 门槛；原有 data URL 背景在迁移提交后才移除旧偏好。
- 中文 composition 与 229 保护，候选确认结束瞬间防误发；WebView2 尺寸变化／唤回后延迟恢复焦点、选区和滚动，组词期间延后执行。
- 话题栏折叠／展开并记忆；没有打开话题时也能展开。顶部人数副标题移除。代码块按三个反引号。

## 验证与证据

- 首轮实际 WebView2 验收 50 项通过，包含原有媒体、搜索、Markdown、4% 缩放和本轮表情包、GIF、命令、组词、大背景；结果在 `outputs/2026-10-15-聊天入口与输入/native-first-50-checks.json`。
- 后续增加侧栏与关闭重开检查，最终结果另存本目录对应 outputs；以最终记录为准。
- 原生鼠标通过隔离宿主 DevTools Input 调用，避免只靠合成 DOM click。验证桥仅 `--verify` 可用，不进入正常窗口路径。
- 系统输入法实测使用 computer-use：先复现左上角组词框；修复后 n、i 的拼音组词跟随底部输入位置，space 确认“你”仍留在输入框，没有发送。仅代表本机当前输入法与运行时，其他第三方输入法、跨屏 DPI 和全部窗口形态未穷尽。
- 真实系统输入法检查与 Chromium `Input.imeSetComposition` 检查分别记录，后者不冒充系统候选窗口验证。
- 上游 TypeScript／ESLint 检查通过；项目完整检查首轮 289 项通过，交付前复核见 outputs 中最终日志。
- `F:/agent规范` 索引检查通过，19 个条目、0 错误。

WebView2 锚点恢复的背景参考：[运行时问题 #5675](https://github.com/MicrosoftEdge/WebView2Feedback/issues/5675)、[独立项目的修复记录](https://github.com/observer130/lanmark/commit/ba451f06178dbb08d6f97b9f5d53b46b26aca5e9)。本项目实现和本机观测是交付依据，不将上游问题推断成所有输入法的唯一原因。

## 数据与回退

正常预览升级前已关闭窗口并保存原构建、EXE、清单、用户存储与窗口偏好的本地快照，位置 `tmp/chat-input-20261015/before/`，文件 SHA-256 清单在同级 `profile-snapshot-manifest.json`。测试使用既有合成 profile，不覆盖正常预览 profile。正式日记仅做 SHA-256 前后核对。

成品入口仍为 `outputs/2026-10-15-Telegram聊天预览/拾页对话预览.exe`；本轮证据 `outputs/2026-10-15-聊天入口与输入/`；临时脚本、旧运行版和恢复资料 `tmp/chat-input-20261015/`。未清理用户记录或升级快照。

## 保留的边界

统一正式消息格式、归篇、撤回短期缓存、历史身份、机器人／回顾／提醒、正式个人资料、手机和自建服务器同步仍按既有需求后续实施。表情包支持用户准备好的普通图片/GIF；不承诺能直接解析微信内部专有／加密文件。磁盘和浏览器的实际可用额度仍有限，保存失败保留旧背景并提示。
