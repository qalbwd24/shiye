## 修复后的行为

- 新上传、备份导入的不同字节同名附件可以共存，不再自动生成文件名冲突。复用需要 SHA-256、字节数、类型和用途一致。
- 去重仅将新暂存文件列入清理，已登记的原 ID 不会被作为冗余文件删除；旧引用、旧记录及其时间元数据继续保留。
- 上传按接收字节原样写入，保留文件内容中的 EXIF 等字节；登记浏览器 `File.lastModified` 为可选数字毫秒 `lastModified`，登记首次接收时间 ISO 字符串 `importedAt`。未提供或无效的文件时间不编造；相同内容的再次上传保留已有记录时间。文件修改时间不等于拍摄时间。
- 旧冲突仍能比较和保留两份。选择一份时先在页面居中对话框比较，必须逐篇勾选日记，不默认选中任意范围。后台要求 `targets:[{id,revision}]`，缺少范围或版本过期均拒绝。
- 已同时包含两份附件的日记禁止替换合并，提示保留两份。未选中的日记保持不变。
- 每次新附件替换记录作用日记与替换前后 revision。可在未继续编辑、历史仍可用时撤销；否则提示打开编辑历史，避免覆盖后续编辑。旧版记录没有作用范围时只展示相关日记，明确这些不是已确认的受影响范围。
- v1/v2 恢复及去重统一映射当前内容、Markdown 镜像、历史正文中的 `/media/ID`，以及附件数组和旧格式媒体引用；媒体原字节及时间字段随备份保留。
