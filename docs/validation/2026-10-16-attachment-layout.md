# 图片发送弹窗布局修订 ui3

依据用户 2026-10-16 截图，当前 0.9.20 普通窗口已经做过部分文字／图标缩放优化，但图片发送弹窗仍有实际布局遗漏。此前 ui2 主要修订动画与等待，也没有解决此处；不能以“当前是旧版”解释掉缺陷。

根因：上游 Button 默认 width:100%，加入取消按钮并横排后，发送按钮仍占整行宽度，取消被挤窄；只检查按钮高度及同排，没有检查文字单行、宽度与横向溢出。发送图标 32px 与缩小后的表情按钮也不协调。

## 修订

- 取消按钮最小 64×36px，文字不换行、不被压缩，去掉与 gap 重复的右侧外边距。
- 纯图标发送按钮 44×36px；带“保存／下一步”文字时按内容宽度，最大 88px，保留功能。
- 发送和表情图标 20px，图片预览编辑／遮罩／删除图标 18px，点击区域 32px。
- 图片说明区域 flex 可缩小、内容可换行滚动；表情按钮不再使用负边距侵入输入区域。以上控件不随消息字号同比放大。
- 页脚容器不足 340px 时，说明与表情保持一行、发送／取消移到下方同排，避免大字说明变为一字一行；只保留父输入滚动区，避免双层滚动条。
- 自有样式标记由 AttachmentModal.tsx 的本地模式直接声明，避免编辑说明、缩放等重渲染移除外部追加的 class；同时覆盖本地自有的 shiye-symbol-button，不能只处理上游表情按钮选择器。
- 本轮仅修改聊天自有适配层、样式及验收代码，不改日记数据格式，也不覆盖另一个会话的富文本文件。

## 验收范围

实际原生 WebView2 合成会话中，检查 100%、152%（字号步进 4%）、200% 字号和 420px／320px 弹窗宽度六种组合：取消文字单行，发送宽度合理、无重叠越界，按钮同排，图标保持 20px，弹窗没有横向溢出，说明内容区至少容纳三个当前字号的汉字。输入多行说明后重复检查。增加原生截图留证，再检查图片取消、已有草稿末尾光标、图片发送及原有动画回归。

首轮几何检查复现发送按钮宽度错误，修复框架重渲染覆盖 class 后通过。随后视觉检查仍看到窄弹窗说明几乎一字一行，因此增加窄页脚分行和输入宽度检查；不把原先 112 项几何通过当成视觉问题全部解决。

最终实际检查 118 项聊天、9 项独立图片均通过，无运行时异常；六组中发送宽度均为 44px、取消均为 64px，说明文字从 16px 放大到 32px 而图标保持 20px。窄页脚的说明内容宽度 184px，200% 时不再一字一行。已打开并视觉检查 200%／320px 的原生截图：按钮单行、没有越界，说明可以横向阅读，附加工具图标不遮文字。

原生 C# 编译、聊天 vendor TypeScript 全量检查、AttachmentModal.tsx 的 ESLint、本轮相关文件格式检查通过。完整 npm run check 通过模块检查和根 ESLint，但仍在其他会话正在处理的 3 个富文本文件格式处停止：public/features/rich-text-lab-store.js、public/features/rich-text-lab.js、public/shared/rich-document-archive.js。没有自动改写这些其他工作文件，不把本轮隔离 UI 检查成功当成总检查通过。

产物目录为 `outputs/2026-10-16-附件布局优化/candidate/`；截图为其中 attachment-layout-200pct.png；最终报告副本与交付清单在同目录的上一级。临时中间文件继续使用本项目 tmp。
