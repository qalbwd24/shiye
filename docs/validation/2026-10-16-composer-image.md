# 输入框与独立看图修复 ui6 · 2026-10-16

用户反馈ui5输入框拖不动、长文字无法滚动、左侧图标重叠、提示文字位置异常；随后要求图片窗口记忆尺寸，直接弹出，避免先放大再缩回。

## 复现与原因

outputs/2026-10-16-输入与看图修复/baseline-ui-check.json 保留旧版实际指针失败：拖动条能命中，内层输入高64px，外层滚动区却只有40px，真实拖动不能增大可见区域。此前键盘调整和程序scrollTop检查不足，不能视为鼠标／滚轮验收。

内层输入、外层滚动容器与上游clone测量同时限制高度，形成裁切和双层滚动；文字使用独立字号／1.65行高，placeholder仍按旧字号／1.375计算。上游AI按钮绝对定位在附件按钮位置，输入后出现即重叠。

看图原流程先挂载内嵌MediaViewer并执行ghost放大动画，拿到原图后再关闭并打开原生窗口；用户看到的是两次切换。

## 修订

- CSS把高度／滚动约束放在真正外层input-scroller，正文只负责内容高度；提示与正文共享字号、行高及对称留白。输入拖动条放在footer内部独立热区，支持指针捕获取消，拖动时暂停自动收起。
- AI／富文本展开按钮使用独立的布局位置，不覆盖附件／正文；图片说明同步统一排版与外层滚动。
- useShiyeInput.ts在明确要求恢复末尾时等待编辑器布局，再将外层滚到内容底部；手动滚轮回看不触发该操作。
- MediaViewer.tsx直接加载原图并转交独立查看器，成功时关闭内部状态，主窗口不经过内嵌预览与ghost动画。加载失败允许恢复内嵌查看，等待有超时。
- ImageWindowMemory.cs在聊天状态目录的image-window.json独立按屏保存位置、尺寸、最大化；原窗口设置和日记正文不改。显示器身份／DPI适配复用DisplayMemory，保留断开屏记录，最小化不记成屏外坐标。
- 独立窗口在显示前应用记忆，图像加载就绪后再显现；读取期间和查看期间维持主窗口忙碌状态，避免自动吸附收起与图片弹出互相打断。

全程使用tmp/telegram-preview-20261015合成profile，不修改普通窗口草稿或发送真实测试消息。构建、每轮失败记录、最终验收及正式启用回读位于 outputs/2026-10-16-输入与看图修复/。真实双屏、跨物理接口和热插拔仍待硬件验收；最终计数与启用状态在下段更新。
