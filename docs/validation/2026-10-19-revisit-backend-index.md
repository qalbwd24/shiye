# 朝花夕拾后端来源目录复用

用户要求以后端性能为本轮范围，参考 DSH 的技术路线，前端继续独立优化。本轮不修改前端文件、传输字段、业务规则、游标语义或正式数据结构。当前前端入口按实际 status 回读；开发文档的 u43 是中间阶段，开工时运行 ui44/API0.9.27。

## 实现与正确性

来源目录在推进 tick、历史页、来源和评论上下文之间复用。每次请求仍按当前 entries、media、messageStore、chatJournal.rooms/withdrawals 的完整内容计算 SHA-256 指纹；不依赖数量、最大更新时间或假设存在的 db.revision。正文、软删除、隐藏、草稿、分类标签、媒体元数据、规范单元、房间信息和撤回变化均失效；写事务整库克隆而来源内容未变时仍可复用。

缓存仅含不可变来源读取会话，不缓存认证、请求响应、规则或每实例游标。不同实例可以复用完全相同的来源目录，规划器仍独立读取各自规则、随机日、投递及评论。相同数量/时间但内容不同的库不能命中过期目录。指纹与捕获使用同一次输入读取。

最多保留一个目录，估算保留额度上限160MiB，超限不缓存；替换前先释放缓存持有的旧目录，构建失败不返回旧结果。额度是对象/字符串的保守估算，不是整个 V8 堆或 RSS 的硬上限；原有96MiB候选转换缓存仍独立存在。这一阶段以减少重复解析、克隆和建索引为目标，尚未实现仅含调度字段的轻量索引。
