## 打开与测试

在 D:\拾页运行 `npm run dev`，打开 `http://127.0.0.1:18766/?quick=1&richdoc=1`。设置中的“组件与 AI 数据”图文试写入口也提供链接。开发服务的 `/api/health` 应包含 `contentFormats` 中的 `richdoc`；只有旧版本号而没有此能力字段时，须先正常更新开发服务。

启动仍为“上一篇／分类”选择，默认上一篇，方向键选分类后 Enter 新建。新篇仍不因空白缩进保存；标题 Enter 到正文、原时间快捷键（默认 Alt＋T）、分割线与自动换行沿用已有写作入口。分类、字体、背景、设置和托盘控制继续由原模块负责。

试写后粘贴图片，预览确认仍默认 Enter；可选择保留原件或原有压缩档位。确认上传后在光标位置插图；同图两次插入有不同 occurrenceId 和 insertedAt，但可以共享原文件。图片双击使用原大图查看器，显示尺寸不修改原字节。当前默认居中、75% 正文宽度；原试写页的宽度、对齐、图注面板尚未移入快捷设置。

保存后重开、继续上一篇，检查文字、空行、分割线、图片位置。开发新篇的权威正文为 body，HTML 为服务端生成的兼容阅读投影。非空旧模板仍使用原 Markdown 路径；选择旧 HTML／Markdown 日记不会自动转换。

## 数据与时间

- 开发库：`var/dev-data/`；批量转换候选：`var/migration-lab/full-20261016-a/`，两个目录用途不同。
- 正式旧库仍位于部署配置指定的原路径；本批处理只通过 GET 读源。
- 正文手打时间仍留在原文。段内硬换行时间由 `legacy-time-segments` 解析成可重建索引；图片 insertedAt 独立记录，不替代手打时间。
- 新篇正文编辑由服务端维护 contentEditedAt。改分类／标签不会推进此时钟。历史图片未知插入时间保持 null，文件入库、拍摄、修改时间都不冒充插入时间。
- 图片实际原件继续独立存在 media。新格式备份恢复须映射当前及历史 body 的 assetId，并重新生成 HTML 投影；已用虚构图片验证 JSON 加密和流式恢复。
