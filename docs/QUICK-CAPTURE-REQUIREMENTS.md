# 快捷记录与统一新建流程

状态：2026-09-22 第四轮需求核对；0.9.1 已完成快捷页正文同步和字数统计修补并发布本地服务。本文继续记录设计依据；更完整冲突交互仍需后续迭代。

开发进展：2026-09-22 已新增分类弹窗、快捷窗口流程、延迟创建保存、幂等接口、冲突选择和 Windows WebView2 宿主；本轮补齐原生 X 关闭握手、分类选择取消、编辑器关闭前提交、正文重复同步和字数统计回调，完成隔离与浏览器验收并启动 0.9.1。接口、剩余边界和下一步见 [并行开发交接](QUICK-CAPTURE-DEVELOPMENT.md)。

## 已确认

- 快捷入口每次打开新建一篇；保留大标题，选完分类直接聚焦正文。
- 快捷入口与正式新建入口都先选分类；支持指定一个现有分类作为默认分类。
- 分类管理可拖动、上下移动；所有分类展示使用同一排序规则，默认分类标记不改变排序。
- 实际编辑后自动保存，正常关闭前完成最后保存；保存失败保留窗口。
- 无内容新记录关闭时不创建空白日记；自动缩进和默认填充不视为用户编辑。
- 可跳回上次经快捷窗口编辑的有效日记；可打开主窗口定位当前同一篇，不能复制创建。
- 移除正文中间两行常驻工具栏；共享编辑核心和保存协议，不另造编辑器。

## 已确认的边界规则

1. 默认分类为库级偏好，两个入口共用。弹窗预选默认分类，↑/↓移动选择，Enter确认；Esc或关闭分类弹窗取消本次新建，不创建记录。确认后正文获焦，保留大标题但不先跳到标题。
2. 打开已有日记不重新询问分类。每次快捷启动进入新记录；若复用正在编辑的小窗，先保存当前记录再开始新篇。
3. 仅标题有内容或仅有附件都属于有效记录；只有空白字符、自动缩进、默认分类不创建记录。用户清空本次新建内容后关闭应不出现在正式日记列表；已有日记清空内容不自动删除。
4. 快捷编辑历史跨窗口重启保留，按快捷窗口实际编辑顺序追溯，而非日记记录日期。上一篇若为空白，继续向前查找，直到有效记录；只有标题或附件也算有效。空白启动不更新历史。不自动恢复已删除记录，已删除或不可访问项也跳过；找不到时提示暂无上一篇。该追溯不是扫描全部日记，也不自动清理被跳过的记录。
5. 正常自动保存沿用编辑核心的队列与输入法保护，停止输入约半秒保存，关窗补最后一次。界面明确显示失败，不假报保存成功。
6. 主窗口与快捷窗定位同一记录ID。内容一致时无需冲突提示；有可靠历史依据证明其中一份是另一份的旧版本时自动更新到后继版本；两边独立修改或无法证明继承关系时弹窗选择。详细规则见下节。
7. 小窗尺寸、位置和置顶状态可记忆；打开新篇自动进入正文，窗口位置超出当前屏幕时修正到可见范围。
8. 独立快捷启动入口供用户绑定系统热键；不擅自修改全局AutoHotkey脚本。快捷入口与普通入口区分明确。

## 冲突处理规则

适用当前同一篇日记的主窗口与快捷窗口并发编辑，不等于已实现云同步。统一比较标题、正文源格式及内容、分类、标签、附件及其顺序等可编辑内容，不把更新时间或派生渲染差异单独当成正文冲突。

- 内容一致：对齐已保存版本与状态，不创建副本。
- 单向历史继承：只有版本链/历史快照能够证明一份是另一份的前身、且旧版本一侧没有新的独立改动，才自动使用后继版本。更新时间更晚、文字更多、包含旧正文，都不足以证明继承关系。
- 双方从同一历史版本各自编辑，即使一边时间更晚也算分叉，不能自动覆盖；缺失历史证据时按分叉处理。
- 弹窗明确标注“本窗口内容”和“已保存内容”，显示标题、更新时间、正文差异、分类/标签及附件增删或调序，不仅提示一个笼统的冲突错误。
- 操作包括：使用本窗口内容；使用已保存内容；两份都保留（当前库版本仍为原篇，本窗口内容另存新篇）；暂不处理（保留输入并返回编辑）。默认不预选覆盖动作。
- 覆盖前保留可恢复历史；另存新篇保留分类、标签及媒体引用，不重复复制媒体文件。新篇标明与原篇的关系，允许改标题；不得冒充原篇的全部历史或复制其评论成新的评论。
- 用户确认时重新校验保存版本，弹窗打开期间若另一窗口又更新，重新展示差异，旧选择不能覆盖更新后的第三份内容。
- 冲突未解决时保留未保存内容，关闭请求不能被当作默许覆盖。两窗口均无待保存修改时可直接刷新到同一版本。

## 键盘操作：本轮与后续统一原则

用户明确要求分类弹窗支持上下选择、回车选定，并将这种方式推广到日记中的多数功能列表。

- 本轮：分类弹窗↑/↓移动高亮、Enter选中并聚焦正文、Esc取消；可见高亮项自动滚入视区，支持搜索后选择。输入法候选词和组词确认优先，不能误触发分类确认。
- 后续：建立统一功能菜单/命令面板，可由可配置快捷键唤起；搜索过滤、↑/↓选择、Enter执行、Esc关闭。分类、标签、模板等选择器复用相同交互约定。
- 菜单关闭后恢复原焦点和正文光标；菜单未打开时不占用正文方向键。保留Tab的正常控件导航与既有正文空两格约定，作用范围必须明确。
- 键盘高亮和“默认分类”标记分别表达临时选择与持久设置，不混为一谈。以后新增功能优先接统一命令注册表，避免每处重复维护快捷键。

## 讨论变更记录（后续优化参考）

- 用户要求保留大标题，否定了快捷窗默认隐藏标题的初步建议；正文仍为初始输入焦点。
- 用户确认默认分类共用、空白不保留、重复唤起先保存再新建、窗口习惯记忆等规则。
- 用户将“上一篇”补充为跳过空白继续向前寻找，而不是只持有一个可能为空的最后记录ID。
- 用户要求有历史继承关系的两份内容自动更新；只有独立变化才提示如何保留。上面的证据判断、差异展示、保留两份和确认时再次校验，是对该要求的实现细化。
- 用户要求本次交流记录到项目文档，作为日后功能列表与键盘操作的设计依据；本节与上节承担该用途，不写入用户日记库。

## 与编辑核心的协作边界

编辑核心任务正在修改 body-editor、persistence、editor-document、main.js 等文件。本任务先维护需求与窗口/分类模块设计；未协调稳定接口前，不改写这些正在变更的文件，不切换共享Git分支、不发布包含其半成品的版本。

需要的接口：读取/替换文档、聚焦正文、内容变更通知、输入法组词状态、保存队列flush与pending、记录revision、打开指定记录ID。小窗/新建流程负责未落库记录的生命周期；编辑核心不应自行决定默认分类或创建空记录。
