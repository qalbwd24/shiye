# Android 服务器连接与服务适配

2026-10-18用户授权：先将已验0.11保留数据安装到手机用于UI手测；后端的数据格式/算法继续由对应会话优化，本会话继续适配实际接口，含朝花夕拾。目前电脑可作为服务宿主，将来迁到云服务器，手机仍保有完整本地资料。手机0.11与本地0.12候选分开，不因候选构建自动升级手机。

## 当前已实现的客户端接缝

- 原生设置新增“服务连接”，单独的地址保存、服务发现、可用服务和已有独立实例状态。默认空地址为离线，不自动扫描局域网、不自动上传资料，也不自动创建实例/绑定/修改规则。
- `BackendServices`固定调用health、服务目录及指定实例动作；health和catalog能力/结构通过才显示兼容目录。完整返回JSON保留未知字段，不按软件版本号猜服务能力。
- 网络工作使用独立执行队列，不占日记LocalStore保存队列。地址保存成功与网络连接成功分开；上次目录按地址隔离落在私有偏好，重开先显示带“快照”标记的本地目录，失败不清空已保存目录。
- 读取实例状态沿真实instanceId/scope，未来feed、source、media、comment、withdraw等固定动作接缝已有白名单；当前UI只读status，没有启用自动收件或业务写入口。不存在的AI服务不显示成可用。
- 新增Android INTERNET权限；仅原生固定客户端使用配置地址。网络安全策略只允许localhost/127.0.0.1的HTTP，其他服务需HTTPS；WebView的本地资源拦截、导航和网络guard保留，没有增加网页任意URL/任意请求头桥。
- 服务地址可带部署路径前缀，禁止URL内账号密码/query/fragment、跳转跟随和不安全TLS覆盖；响应/缓存有限额，401锁定/409冲突/超时等分类反馈且不显示远端原始正文/密钥。地址代际校验阻止旧请求覆盖新连接。

接口审计见[服务审计](ANDROID-SERVICE-API-AUDIT-2026-10-18.md)，原生签名与99项实际隔离HTTP断言见[传输层](ANDROID-SERVICE-TRANSPORT-012.md)。这些功能不等于完整数据同步完成。

## 当前电脑本机服务与未来云端

现有正式API仅loopback监听，Host限制为localhost/127.0.0.1，写请求有本机来源检查，访问锁仍有效。不能将手机填电脑局域网IP解释为已连通，也不通过改监听/删除Host或Origin检查解决。原生POST暂用后端既有`X-Diary-Client: desktop`兼容指示，它不是身份认证，不能作为开放公网的认证方案。

开发阶段可在专用AVD使用明确端口的`adb reverse`访问电脑隔离库，手机没有配置该测试转发。未来服务器需要后端发布受保护的部署/认证协议，或明确受保护网关方案，再接认证适配和HTTPS地址；当前客户端保留默认系统TLS验证，不提前伪造Bearer/Cookie登录成功。服务器锁定返回401时当前提示在电脑解锁，不把本地密码写进连接配置。

2026-10-18补读最新[SYNC-FRONTEND-CONTRACT](SYNC-FRONTEND-CONTRACT.md)与手机独立测试验收：后端已装配独立shiye-sync协议1测试服务（18769及独立18779测试库），临时真机应用5项通信通过，不能继续笼统称路由未装配。但正式产品Repository未接，0.12日常业务服务客户端也不是同步客户端，不能只改地址到18779。后续使用createSyncClient/storage port契约，先接配对/系统私有凭据、libraryId/epoch保护及SQLite内容+outbox同事务，再接inbox游标/原件任务，未发请求保持本地编辑流畅；地址迁到云需同库身份/认证/回执/媒体一并迁移。算法部署位置不影响[本地完整存储](ANDROID-LOCAL-FIRST-STORAGE.md)约束。

## 后续接入顺序与不变约束

1. 后端发布稳定同步/认证能力后，接完整本地Entry/消息/原件Repository与保留式身份映射；原SQLite/媒体/TL IDB不直接删除。业务写入与outbox同事务，本地ACK独立于远端ACK。
2. 将规范会话身份映射接到服务选择/实例创建/绑定。不能用标题或裸TL数字作为跨端会话身份；创建UUID/请求参数、绑定revision与配置revision独立保留。成功ACK后才显示已接入。
3. 实例feed按instanceId独立游标接入持久inbox，幂等落盘后再推进本地收件位置；本地列表先显示，后台更新，不能每次切页空白刷新。不能将多个实例全部投进旧固定房间。
4. 按实际正文/投递契约渲染朝花夕拾及原文媒体；来源、deliveryId/batchId/instanceId与引用固定，旧实例解绑后不重写旧回复目标。评论/撤回使用持久operationId/原实例，重试不能生成新身份。
5. 朝花夕拾由服务器执行和保存运行进度，手机改配置/绑定、读取投递；不能将手机旧运行cursor同步覆盖服务器。数据层与算法仍共用电脑实际契约，不在手机另写近似切段算法。

当前未实现：远端认证、自动收件渲染、create/bind UI、服务评论/撤回outbox、完整本地Repository/同步冲突迁移、TLS实连与公网部署。0.11手机UI可继续测试，不把0.12接缝说成手机已联网或朝花夕拾已互通。
