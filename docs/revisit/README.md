依赖方向：数据来源→标准来源契约→回看引擎→推送服务；评论服务使用固定来源/组引用；随想通过接口读来信、发评论；运行器只调用推送服务。核心引擎不得反向依赖后五项。

共享契约复用已有SourceRef、MessageUnit/richdoc、UTC时间、媒体assetId/occurrenceId；不重新发明一套日记格式。第一步增加的是引擎输入输出的版本化边界，不迁移旧日记。

## 每步的完成标准

1. 写清职责、输入输出、错误及明确不承担的职责。
2. 移出相应代码，保留旧入口兼容层，避免其他会话改UI时跟着改接口。
3. 独立测试通过，同时原后端集成回归通过，核对编号、分组和时间没有变。
4. 更新本入口、对应子项目和验证记录，标明“源码完成／隔离验证／正式启用”的区别。
5. 再进入下一步；六项主体已有各自代码边界，第五步UI仍由UI会话优化，第六步仅提供已验后端控制。通用备份合并映射、正式集成/部署、长期运行仍另行处理，不把源码拆分等同产品验收完成。

各阶段产物放outputs/revisit-decoupling/stage1至stage6，临时基线和隔离文件放tmp/revisit-decoupling对应阶段。验收见[阶段1](../validation/2026-10-17-revisit-decoupling-stage1.md)、[阶段2](../validation/2026-10-17-revisit-decoupling-stage2.md)、[阶段3](../validation/2026-10-17-revisit-decoupling-stage3.md)、[阶段4](../validation/2026-10-17-revisit-decoupling-stage4.md)、[阶段6](../validation/2026-10-17-revisit-decoupling-stage6.md)。原实现说明和既有候选验收仍见[REVISIT-PUSH](../REVISIT-PUSH.md)。
