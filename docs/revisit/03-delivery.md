# 子项目3：推送与状态服务

2026-10-17 用户授权第三步，源码主体拆分与针对性隔离测试已完成，未部署。仅数据层与隔离测试，不覆盖旧日记、不操作正在运行的窗口。原src/server/domain/revisit.mjs、routes/revisit.mjs逻辑移入revisit/delivery/；保留旧接口，HTTP路由只做入参/认证和结果适配。全项目结果见[阶段3验收](../validation/2026-10-17-revisit-decoupling-stage3.md)。

本轮补查发现：旧代码把31天的手动补看上限也用于自动停机续推；每日分段还可能切在分钟中间。本轮将修正为自动续推不受手动跨度限制、每日处理至完整分钟末，计划只读计算，投递/分组/游标原子提交。失败重试、并发、重启和旧正文保护均在隔离库验收。

接收来源目录和回看引擎候选，负责启用/暂停、首次起点、手动补看、分钟闭合、停机续推、跨轮去重、稳定投递编号、冻结分组、顺序分页和实时来源解析。保存引用，不保存另一份可编辑源正文。

存储先继续使用db.revisit和拾页mutate串行事务；拆模块不等于拆数据库。定义存储端口，后续才考虑本地独立库或服务器实现；旧入口/API保持兼容。

## 不漏发、不重复的实际边界

- 同一规则版本/SourceRef/回看时刻生成稳定投递ID。重复窗口、手动与自动重叠、多个服务对象或HTTP请求重试均在同一写队列重新读取最新进度并去重。
- 投递、固定组、sequence和自动游标同一事务落盘；来源/引擎计算报错、计划过期、写临时文件或重命名失败都不推进内存和原文件。提交成功但回执丢失时，重启重试由已有投递ID去重。底层仍是既有copy-on-write及临时文件rename，不声称已实现断电fsync保证或多进程共享库并发写。
- 首次自动tick从当时开始；之后停机超过31天可按最多一天连续推进，分段至完整分钟末，避免同一分钟被日上限切开。31天限制只约束手动补看；手动补看不移动自动游标。仍在进行的分钟等待闭合，系统时钟倒退时保留原游标等待追上。
- 改发送者名称/头像不改变投递身份或游标；改规则会开启新的ruleRevision/起点，旧投递和评论不重绑。启用/暂停沿用原开关重置起点策略，暂停期不是自动续推范围，可手动补看。
- 自动只处理当时可读、时间明确且命中规则的来源。未知时间、隐藏/草稿/删除/撤回及不存在的日历日期按已有规则排除；后来才导入或修复的历史记录需手动补看。不能把这些排除项误称为系统已经投递。
- 固定组一经提交不追加成员，避免旧评论目标改变；手动按精确区间补看可能与另一部分记录形成同分钟的另一组，已有投递仍不会重复。

## 状态归档恢复

GET /api/revisit/archive返回format=shiye-revisit-state、version=1、sourceFingerprint、state、checksum和当前targetToken。包中保存推送元数据/来源引用及评论，没有另一份日记正文；不读写源文件。

PUT接收{archive,expectedToken}，走同一串行mutate。必须checksum有效、来源条目/规范消息/聊天/媒体快照相同、游标/序号/投递ID/固定组/评论关联合法。目标没有推送进度和评论时才能恢复；完全相同的包可幂等重试。目标状态已改变、已有不同进度/评论或来源不同则409拒绝，避免旧备份回滚或复活撤回正文。

这是后端状态组件的同源快照往返，已做双隔离HTTP库及重启验收。通用备份合并恢复会重新映射日记和媒体ID，尚未接入此状态映射；普通open-data日记导出也不夹带推送状态。不能把本步状态归档测试当成全库任意合并恢复已支持，后续需单独设计映射及冲突策略。
