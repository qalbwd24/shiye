# 随拾页后台自动续推

2026-10-17用户明确要求：朝花夕拾随拾页后台启动，关闭窗口退到托盘后继续；后台/电脑重启保留原进度，不再要求每次点启动。本要求取代第六步初版“重启后默认停止”的约定。

## 行为与实现

- 正式`server.mjs`在构造服务时设置`revisitAutoStart:true`。服务监听成功后，已启用的规则自动启动同一个受管运行器，默认30秒检查；无须打开随想或保持页面。可组合的`createDiaryServer`默认不启动，隔离测试/专用宿主显式选择，避免测试服务偷偷修改游标。
- 沿用`db.revisit`已有配置、日期抽选、游标、delivery/batch身份和评论；自动启动不调用配置保存、不重设游标、不重新抽当前周期日期、不复制正文。首次无进度仍从启动时刻开始；已有进度则按原游标补齐停机期间已到期消息，投递去重。
- 开启/解锁后的正常已授权请求可恢复运行器；访问锁未解锁时不绕过，正常解锁后自动续推。不保存密码/会话到磁盘，不开放任意URL或新控制接口。health新增`revisit.autoStart:true`供核验正式入口策略。
- “停止推送”暂停本次后台运行，后续普通查询不偷偷重启它；显式“启动推送”恢复。下次后台重启会再次跟随已启用规则启动。要持续关闭则取消启用并保存。页面退出/关闭设置/退托盘不调用stop。
- 后台关闭取消该实例的认证、请求和等待；沿用同一host的启动单飞及epoch检查，避免同时手动/自动启动出两个循环或迟到授权复活实例。没有新增Windows开机项、系统服务或另一个CLI进程。

代码：`server.mjs`、`src/server/app.mjs`、`src/server/routes/revisit-runner.mjs`，底层runtime和持久状态算法保持。设置页提示同步该规则；ui24仅在冻结ui23上改这句提示与运行修订，不混入共享工作区的其他UI候选。
