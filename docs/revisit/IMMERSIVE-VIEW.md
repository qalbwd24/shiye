# 朝花夕拾沉浸阅读与消息回复

2026-10-17用户对定时图文演示的最新反馈，替代早期默认评论整组的产品约定。

2026-10-17最新补充：**历史消息必须与本人发出的消息共用同一套外观和渲染，仅左右位置不同**。具体 UI 已在 ui23 完成并安装启动，历史来源与 outgoing 语义不变；此前18项联调仅为旧阶段证据，新的外观/媒体/提示验收见文末。正式朝花夕拾后端未部署、推送未启用。

## 显示

- 字体、字号与缩放、行高、Markdown、代码/链接/引用、纯表情、图片/视频、气泡颜色/透明度/圆角/阴影/宽度和留白，均沿用本人消息的统一组件与当前偏好；不能为朝花夕拾维护另一套近似样式。本人消息外观调整后，历史消息同时生效。
- 位置与来源语义分离：历史消息仍是历史来信，不通过篡改isOutgoing、senderId、时间或来源来套用“本人”外观；也不伪造已发送/已读状态。前端将外观选择与左右排列独立处理。

- 与随想普通消息共用气泡、Markdown、图像和时分；历史来信位于本人消息相对一侧。聊天区不需要发送者头像、发送者名、日记标题、重复的年月日时分秒或常驻查看链接。
- 默认在切换历史日期时给一条轻量系统式提示，如“正在回看 24-10-18”；设置允许改为每条简短日期或完全隐藏历史日期。它们都是客户端呈现偏好，不改变来源时间或投递信息。
- 只隐藏已识别且与消息originalAt吻合的开头独立手打时间标记；代码、引用、普通正文日期或不匹配时间保留。原始正文仍由后端完整保存，查看原日记保持原样。
- 图片、视频按正常媒体显示，保留真实图注，去掉自动拼入的“图片／视频”占位说明。
- “查看原日记”进入消息右键菜单；时分和原始时间仍是消息属性，来源、分类、ID与评论关系保留。

## 回复

- 无显式引用：发送时绑定本地已接收、可查看的最近一条历史消息，按显示时间排序，不受早期手动组选择或迟到旧投递干扰。
- 显式引用：绑定被引用的历史消息，沿用普通聊天的引用预览。不再使用“正在评论某一组”的常驻目标条。
- 两者均将deliveryId与固定batchId交给既有后端；后端验证deliveryId属于该组，再将评论关联到稳定SourceRef（entryId/unitId/可选媒体对象）。可以从原日记按篇读取评论，并保留单条锚点，评论本身不参加回看。
- 旧组评论与旧API参数保持兼容，不回写或重解释既有评论；当前新发消息的默认行为改为单条。

## 实施与边界

展示文本与日期是可重建缓存，不作为第二份权威正文。来源不可查看/锁定时仍清理媒体与引用摘要。实现与核心链路使用隔离合成数据验收，随后仅将 ui23 UI 安装到日常随想，未部署正式后台或导入合成消息。

前端接入门槛：用相同内容比较本人消息与历史消息，确认普通文字、Markdown和图文的渲染/气泡外观一致；切换左右、主题或消息外观偏好时，两者同步生效，并保留来源菜单、时分、日期选择与回复锚点。早期发现的 own/incoming 背景、宽度、时分颜色及媒体分组圆角差异已通过共享视觉声明修复，不能仅凭复用了 Message 组件判断通过。
