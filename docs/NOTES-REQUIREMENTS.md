## 首版交互建议（待讨论，不等于全部已确认）

1. 独立便签入口。窗口顶部是标签栏，下方为一份图文正文；新建时无需先选日记日期、分类或填写标题。
2. `+` 新建空白标签，可改名；未命名时用“未命名便签”加序号。空白标签也可恢复，但不因此生成空日记。
3. 切换标签保留各自输入、光标/选区、滚动和撤销上下文。快捷键参考常见标签工具，最终仍在统一快捷键清单登记，不占用既有 F14/F15。
4. 自动保存显示保存中、已保存或失败。关闭窗口前等待保存；失败或冲突保留输入并给出重试。中文组词过程不能被切换或保存截断。
5. 关闭标签只结束本次打开状态，便签仍可从列表重开；删除通过单独明确操作进入回收站。可评估“撤销关闭标签”。
6. 正常退出和程序重启后恢复打开的标签、顺序、当前标签及写作位置，不沿用快捷日记的五小时到期规则。异常退出恢复以实际持久化和故障验证为准，不能承诺未落盘输入零丢失。
7. 图片沿用现有直接插入、原资源/出现身份/真实插入时间与排版分离机制；不复制出另一套可编辑正文。
8. 内容长期修改，默认不按日期或空闲时长结篇。归档、搜索、主窗口展示与是否参与日记回忆需要明确规则，不能仅靠“放进草稿箱”隐式决定。

| 路径                                       | 与本次目标的关系                                                                  | 判断             |

| 在现有快捷日记窗直接加标签                 | 能复用编辑器，但其分类、新篇、上下篇、五小时恢复与便签长期续写语义混杂            | 不优先           |

推荐方向是独立视图，共享内容服务；“独立”指入口与工作台状态，不预先决定新建数据库。便签的持久身份/归属与统一内容单元对齐，具体 schema 等后端接口核对后再定。

便签复用项目已有图文组件和 WebView2 SDK，不引入新依赖、不复制 Notepads 源码。

## 接口与并行开发边界

- 前端模块为 `public/features/notes-workspace.js`，本轮由独立 `notes.html` 显式装配。正式主窗入口后续再在 `features/index.js` 接入，本轮不抢改主窗装配。
- 图文内容、便签归属/名称、工作台标签/窗口状态分开定义职责；只保留一份权威正文。不能把 `localStorage` 中的一份富文本当作唯一可靠存档。
- 保存需包含稳定身份和版本校验，多窗同一便签的冲突保留双方输入；媒体、历史、删除恢复和备份必须一起支持。
- 后端会话当前负责统一内容模型：便签本轮不新增持久字段、不接管 `entries`/`chatJournal` 路由、不变更旧数据；后续实施先回读其最新方案与代码。
- UI 会话当前负责聊天：便签不改聊天 vendor、外框、会话排列或发布产物。共享装配、版本与交接文件修改前重新读取并局部合并。
- 首版仍需决定：便签是否进入主日记列表/统计/回忆；关闭标签与重启恢复的具体默认；是否需要显式整理为日记，以及整理后保留何种身份和链接。这些不阻止制作独立视图原型，但会影响正式存储接入。
- 本机 Notepads 既有文件/快照不自动导入、转换或覆盖。导入另行提出并保留来源。

## 后续验收基线

- 隔离库创建至少三张图文便签，分别输入、插图、调整排版并来回切换；保存重开内容和图片身份一致。
- 验证关闭标签、重开、普通退出及进程重启；标签顺序、当前页与编辑位置符合规则。
- 验证输入法组合、快速切换、待保存退出、保存失败重试及同篇多窗冲突，不把失败提示当成已保存。
- 验证历史、回收站、备份恢复及旧客户端/同步的兼容边界，便签不误混入聊天自动归篇或普通日记回忆。
- 正式接入后按既有维护流程更新运行版并核对 health。本轮独立前端服务和宿主已启动，不冒充正式日记 API 的版本升级。
