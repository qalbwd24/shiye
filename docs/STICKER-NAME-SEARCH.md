# 随想：用 /名称 选择收藏表情包

2026-10-18 用户确认：去掉斜杠里的图片、搜索、时间、表情和表情包入口，**仅根据 / 后面的文字检索自己的表情包，方向键选择，Enter发送**。候选需要缩略预览；收藏命名即可，无须再建一条映射。后续ui33已启用五条可见候选与设置内管理排序，见[最新规则](STICKER-SORT-FIVE.md)和[运行验收](validation/2026-10-18-sticker-sort-five.md)；ui32为先前实现阶段。

## 使用规则

- 输入`/`浏览收藏，继续输入名称或名称中的一段文字筛选；如收藏叫“猫猫 开心.gif”，输入`/猫猫`或`/开心`均可找到。同一素材的名字与旧别名匹配后只列一次。
- 候选显示图片缩略图、完整名称及GIF标识。缩略图沿用192px首帧缓存，仅为选择预览；发送仍为原图/GIF原件，不发送缩略图。暂未增加悬停播放完整动图。
- ↑↓或←→选择，Enter直接发送选中表情包，不打开说明/确认页。只移除此次`/检索词`，保留其他输入草稿与原有引用；遵循现有sendSticker发送管线。
- Esc只收起候选并保留文字。没有匹配时Enter不发送任何东西，继续修改名称；若要将这段内容当普通文字发出，先Esc收起候选再发送。Shift+Enter仍换行。
- 中文组词期间候选收起，输入法确认回车不发送。查找不转移焦点到候选，图片异步读取完成后重新核对输入框、会话和检索范围；用户已切换则不向错误位置发出。快速连按Enter不会重复启动发送。
- 沿用现有编辑器的斜杠词检测：段首或空白后、最多24个连续非空白/非斜杠字符，不在代码块触发。长名称和带空格名称可输入其中一段检索；不因此缩短或改写收藏名称（收藏名称仍最多250字符）。普通URL不触发。

## 命名、别名与数据

直接读取现有`sticker:*`资产的`id/name/blob`或后端映射`serverMediaId/media`，剔除已移除、空原件、非图片和超过64MiB项目。名称以NFKC归一化、忽略英文大小写做**完全匹配 > 前缀 > 包含**排序；同分优先手动顺序，未手排时沿用使用次数与稳定ID。所有匹配保留，默认同时显示5行（设置1–5），方向键可继续滚动；不使用AI、拼音推断或联网上传输入文字。

原`mapping:*`中kind=sticker的别名可以继续使用；kind=emoji的数据保留但不列入斜杠候选。旧命令开关字段保留兼容，不再执行旧图片/搜索/时间/emoji命令。被移除的命令词也可以成为收藏自己的名称。输入区笑脸按钮已移除，管理统一从设置→表情包打开；旧收藏、Unicode内容和emoji映射数据保留，管理页不再显示emoji切换按钮。

收藏/重命名/移除后通过`shiye-stickers-updated`重新读取本地目录；输入时只查内存元数据，不逐次读全库、图片字节或请求服务器。候选缩略图按可见项加载，关闭或换查询回收对象URL；异步返回不能污染新候选。

设置页统一为“表情包”，包含管理/排序、总开关、是否匹配已有表情包别名、候选可见数量与旧映射管理。收藏改名仍使用现有update接口；本功能不新增消息类型、接口或存储迁移。原件/尺寸/跨端接口见[跨端媒体契约](STICKER-IMAGE-CROSS-DEVICE.md)。Android可按同一命名/选择规则实现，电脑升级不等于APK已更新；另一会话正在做的普通文字联想是独立触发方式，不由本轮改变。

实现：`previews/telegram-chat/shiye-input.js`与候选缩略样式；`shiye-preview.js`更新设置文案和运行修订号。基于冻结ui31仅替换这三个文件，不混入其他会话的Android/同步候选。验收产物`outputs/sticker-name-search`，临时脚本和隔离库`tmp/sticker-name-search`。
