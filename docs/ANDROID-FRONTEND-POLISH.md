# Android 前端样式与既定数据格式对齐

## 2026-10-17 用户确认

用户认可的“排版”仅指入口结构：打开先进入会话列表；提供独立快捷新建写日记入口；通过底部导航切换到日记查看。它不代表现有各页内部样式已获认可。用户明确当前视觉和细节粗糙，要求参考成熟客户端与已有拾页代码分别优化，不再扩展自创后端格式。

本轮分别打磨会话列表与消息页、日记编辑页、日记阅读列表与阅读详情。保留以上入口，保持快速写不依赖阅读列表；延续 Telegram 移动消息交互和一本日记的整篇编辑/阅读体验。字体、图标、层级、留白、触控反馈、菜单/弹层、输入与键盘布局都纳入实际前端交付，而不是仅换主题色。

## 数据职责

按最新实际实现与开发文档渲染既定数据，保存新消息/日记沿既有入口；不重定 schema、不把 TL 或临时 IDB 称为共同后端协议。以 [消息主体实际实现](MESSAGE-UNITS-IMPLEMENTATION.md)、[现有模型](DATA-MODEL.md)和[安卓映射审计](ANDROID-FRONTEND-DATA-ALIGNMENT.md)核对 canonical richdoc、稳定身份、时间来源、媒体出现与回复/撤回状态。`UNIFIED-DATA-CONTRACT-V1` 的未接入草案不能取代实际 API。只读候选与已持久化单元区分；既有日记和媒体身份不得因视觉变更重写。

云服务器仍未接入。前端可用隔离合成数据验证真实契约与适配，不因此访问或修改正式库/桌面运行版。新增消息的传输接口应与既定服务契约一致，不绕过服务端转换和冲突规则。

## 工作与验收边界

用户在手机 0.2.0 手测基本中文输入可用，继续由用户手动测试；开发代理仅电脑代码/模拟器，不操作或覆盖手机。电脑此前0.2.2的native置顶与迁移19项通过；本轮0.3.0已在主AVD运行，32项定向检查通过。旧多段草稿失败已定位并修复：新建会话ApiChat投影就绪后使用成熟草稿链保存，54字符/五段/空段/空格与emoji经IDB、跨页、冷启和发送精确保持，不做换行归一。原SQLite行、消息和媒体hash保持。历史取证/恢复与备份见[输入优化验收](validation/2026-10-17-android-input-refinement.md)。

并行分工：原生导航/日记列表由主代理；长文写读 WebView 样式由 diary 代理；随想移动样式与草稿接缝由 Telegram 代理；数据代理只读核对实际契约。共享桌面核心、冻结 vendor 与正式数据不代改。所有源码与实际运行/验收结果分别记录，不把截图或 mock 通过当真机完成。
