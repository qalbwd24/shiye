## 分工与顺序

1. **CPU 根因优先。** Sol 建立按进程创建时间、路径校验的完整进程树采样，记录活跃线程与真实窗口状态。主代理分析宿主/UI线程和 WebView browser 的活动来源，设计可归因的对照。只看到定时器或短时 CPU 下降不能结案。
2. **内存按资源归属处理。** Sol 核查素材读取、图片解码、对象 URL、归篇缓存和持久化；主代理决定缓存边界和生命周期设计。隔离合成素材做重复打开/关闭/切换与趋势测量，区分私有提交、工作集、JS 堆和图形资源，不把像素缩小直接换算成内存节省。
3. **发送按阶段测量。** 在已安装 ui15 资产及合成库上测实际输入、optimistic 更新、同步编码、DOM 首次出现、实际绘制/有效透明度和动画结束。先找关键路径，再由 Sol 实施最小修订；主代理负责调度/保存一致性和绘制回弹审查。
4. **验证后更新运行版。** 对确认有效的改动做相关回归及 npm run check，实际查看隔离界面，再使用标准维护 CLI 保存、备份、升级、启动；回读 API/package 版本、运行修订、文件哈希和显示屏记忆。不能把候选写成上线。
