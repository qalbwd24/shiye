# 第一步：图文试写

更新：2026-10-16。状态：独立原型已实现，无界面集成测试通过；真实窗口与中文输入法验收待进行，未替换正式编辑器。

迁入快捷长文前必须对照 [旧功能继承、图片和数据适配基线](QUICK-RICHDOC-INHERITANCE.md) 的 40 项验收；时间戳/换行、图片确认、缩放范围、生命周期与数据适配缺口已列明，不能用试验页替代原快捷窗。手打时间和图片插入时间的区别见该文件第八节。

## 打开与使用

开发服务已运行时打开 <http://127.0.0.1:18766/rich-text-lab.html>；否则在 D:/拾页 执行 `npm run dev`。主窗口/快捷窗口的“设置 → 组件与 AI 数据 → 图文试写”也提供入口。它打开独立试验草稿，不读取正式日记正文，不调用日记写入接口。

正文直接输入和排版；“Markdown 输入”可粘贴 AI 回复或自己写的 Markdown，再插到光标处。右侧用同一份富文档作消息阅读预览，不是已经接入聊天窗口。用工具栏插入图片，或粘贴/拖入本地图片；点击图片显示宽度、对齐、图注设置，双击看原图。

草稿约 450ms 后自动保存，Ctrl+S 可立即保存。Ctrl+加减号/滚轮按 4% 调整文字，偏好单独记忆，不放大工具栏。未保存/保存失败、插图或导入进行中离开会有浏览器提示；不要强制关闭。每个浏览器/来源只有一个试验草稿，多标签页保存会核对版本，冲突时保留当前内容，不自动覆盖。可先导出当前内容，再重新打开。

导入先校验版本、节点/属性、图片签名、大小及 SHA-256；校验期间继续输入会中止替换。短暂提交期间正文不可编辑，提交失败恢复原正文、选区和撤销状态。成功导入时，同一事务保留导入前的试验草稿及其图片，可在“其他 → 恢复导入前的草稿”找回；此恢复副本仅用于独立试验草稿，不用于聊天撤回记录。导出不依赖成功保存，保存冲突或失败时仍可带走当前图文原件。

当前试验库 `shiye-rich-text-lab-v1` 独立于 diary.json 和聊天 profile；其中 drafts 存富文档 JSON，assets 存图片 Blob 原件。清浏览器站点数据会清试验草稿；需要留存请“导出原件”。不自动写到正式 data/，也没有服务器备份承诺。

## 内容支持与边界

| 内容                                               | 本轮实现与验证                                        | 边界                                                                              |
| -------------------------------------------------- | ----------------------------------------------------- | --------------------------------------------------------------------------------- |
| 中文、空格、标点、emoji                            | 节点/DOM 事务保存重开                                 | 实际微软/第三方 IME 候选、组合输入待验；lang=zh-CN 不等于强制切换系统输入法       |
| 标题、段落、换行、加粗、斜体、删除线、下划线、链接 | Tiptap 3.31.3 内容子集，Node 模型检查                 | 只接受 http/https/mailto 链接；标准 `__文字__` 为加粗，斜体用 `*`/`_`             |
| 高亮                                               | `==文字==` 自定义扩展                                 | 具体输入法下的实时输入规则待验                                                    |
| 列表、任务、引用、代码块、分割线、基本表格         | Markdown 解析与 DOM/模型往返                          | 按日记约定，独立一行 `---` 作分隔，不放大前文；代码围栏原文不改，`===` 标题仍支持 |
| 文中图片                                           | 保留顺序，宽度 10–100%、左右/居中、图注、原图查看     | PNG/JPEG/WebP/GIF/AVIF；完整动画、超大图与真实窗口缩放待验，无浮动环绕/Word 分页  |
| 稳定定位                                           | blockId、assetId、occurrenceId、UTC insertedAt 分开   | 仅内容层，尚无评论存取接口                                                        |
| 同文长篇/消息                                      | 左侧编辑、右侧只读采用同一扩展与 JSON                 | 尚未接入现有长篇和 Telegram 消息 renderer                                         |
| 原件导出/导入                                      | 实验 JSON 包含媒体 base64、大小/SHA-256；先验证后替换 | 下载与重新导入的真实浏览器流程待验；不属于正式 `.syvault2` 备份                   |
| Markdown 导出                                      | 供阅读/AI 使用的文本投影，本地图像链接                | 不保留图片排版、图注及定位 ID；JSON 原件为权威，不以 Markdown 回写覆盖            |
| 旧 HTML/Markdown                                   | 用户选文件后只读查看，HTML 清洗                       | 不读取/转换旧库；复杂样式、缺失附件与未知节点不保证完全复现                       |

数学公式、脚注、任意 HTML、嵌入视频/音频、文件节点、上下标、彩色字体及复杂 Word 排版均未纳入这个第一版子集。**不能把它称为完整 Markdown 或正式接入完成**；旧数据格式与原件保留，后续按实际数据扩充/只读降级，不静默删未知节点。富文档恢复若含编辑器会丢弃的属性/节点会拒绝导入，并保留当前草稿。

## 文件与构建

- `public/shared/rich-document.js`：版本、节点校验、稳定定位及字段保留检查。
- `public/shared/rich-document-archive.js`：试验原件编解码、去重媒体/签名/哈希校验，不是正式备份协议。
- `public/editor/rich-document-editor.js`：Tiptap 适配、同内容只读呈现、高亮/本地图片扩展。
- `public/features/rich-text-lab*.js`、`public/rich-text-lab.html`、`public/styles/rich-text-lab.css`：试写入口与独立 IndexedDB。
- `npm run build:rich-editor`：按根 package-lock 固定版本离线打包，产物在 `public/vendor/rich-editor.js`，许可证在 `RICH-EDITOR-LICENSES.txt`。不从 CDN 或 Telegram 服务加载。
- `tests/rich-document*.test.mjs`：真实解析器/Schema、DOM 与 IndexedDB 模拟集成。模拟输入/事务不冒充真实系统键盘、中文 IME 和显示验收。
- `node tools/check-rich-text-stage1.mjs`：不打开原生窗口的检查，输出 `outputs/rich-text-stage1/`。

实现参考 [Tiptap Markdown 安装与 API](https://tiptap.dev/docs/editor/markdown/getting-started/installation)、[表格](https://tiptap.dev/docs/editor/extensions/nodes/table) 及锁定版本的本地源码。官方 Markdown 包仍标注 Beta，故必须保留 JSON 权威来源和往返校验。

## 给用户的实际试写清单（2026-10-16）

用户再次强调快捷窗口是最常用的长篇日记入口，询问怎样测试和接入。当前仅试验页已实现，快捷窗口设置只提供跳转；正文编辑器和正式保存尚未接新格式。试验内容不会自动出现在日记列表中。以下是待人工验收项目，不把既有自动测试结果填作人工通过。

如试验草稿已有需保留的内容，先“导出原件”留一份。用临时测试文字/图片按以下顺序操作：

| 编号 | 操作                                                                                                         | 预期                                                                         |
| ---- | ------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------- |
| R01  | 正文用平常的中文输入法写几段，含空格、标点、换行、光标中间补写，再撤销/重做                                  | 候选确认、空格和正文编辑正常，内容不丢、不误触格式或命令                     |
| R02  | 工具栏设置粗体/斜体/高亮；另通过“Markdown 输入”插入 `**加粗** *斜体* ==高亮==`，以及单独一行的分割线和代码块 | 两种输入都显示相同格式；分割线不把前文变标题；代码原文保留                   |
| R03  | 两段文字中间粘贴/插入图片，再写后文，点击图片调宽度/对齐/图注，双击放大                                      | 图文顺序正确，调宽不压缩原件，放大只影响图片                                 |
| R04  | Ctrl+加减号或 Ctrl+滚轮调整文字，等已保存后刷新                                                              | 4% 步幅，文字比例保留，工具栏不随之放大                                      |
| R05  | 等待“已保存到独立试验库”，刷新或关闭该标签页后以同浏览器/同地址重开                                          | 文字、格式、图片位置/宽度/图注恢复；当前浏览器试验库仍非正式日记库           |
| R06  | 导出原件，追加一段测试文字，再在“其他”导入刚导出的文件；之后恢复导入前草稿                                   | 导入回到导出时图文；恢复能找回追加文字和当时图片。浏览器下载位置由浏览器决定 |

浏览器试写只能验证正文层。全局 F 键唤起、默认中文切换、托盘保留、五小时恢复、窗口位置/DPI、分类及上下篇，要在后续真实快捷窗口试用版中验证；不能用这个页面证明它们已兼容。

## 怎样接回常用快捷窗口（AI 实施建议，尚未落地）

2026-10-16 用户进一步明确本轮核心：**时间戳快捷键、分割线、智能自动换行、插入图片预览，继承并升级即可**。这四项为快捷长文接入的优先验收门槛；不把独立试验页或 Markdown 支持矩阵扩展当作其替代。正文新格式的最小保存/恢复适配仍不可省略，但暂不扩展 AI、朝花夕拾、非线性分块或新日记入口。

| 优先项       | 继承目标与升级方向                                                                                                                      | 实际快捷窗验收                                                                             |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 时间戳快捷键 | 沿用用户当前绑定、时间格式和所选时区；参考现有 dateTimeEdit/richDateTimeInsertion 的句中/选区原位插入、段末另起时间段并把光标放到续写行 | 中文候选确认不触发；句中/段末/空行/选区及撤销重做均正确，不另外自动为段落添加时间          |
| 分割线       | 原快捷键/命令及手输 `---` 继续可用；只插分隔、不删除选中的前文或把前文变标题                                                            | 普通段落后插入、连续插入及中间补写，前文格式保持，光标能在后面继续写                       |
| 智能自动换行 | 继承普通正文的自动缩进/分段开关，时间戳与分割线后的续写位置；列表/引用/代码按各自结构处理，中文组合输入不抢 Enter                       | 正文中间/段末 Enter、Shift+Enter、空段、列表/引用/代码、缩进开/关及手打时间戳工作流        |
| 插入图片预览 | 继承粘贴/拖入/选择文件、确认/取消与键盘操作；升级为光标处文中图片和就地预览，保留原件，能独立放大                                       | Enter 确认、左右选确认/取消、Esc 取消；图片前后续写/补写，原图放大不缩放窗口，保存重开一致 |

已核对可复用依据：`features/editor-input.js`、`shared/date-time-edit.js`、`editor/rich-date-time.js`，`editor/markdown-transforms.js` 的 markdownStructureEnter/paragraphEnter/分割线命令，以及 `features/media-batch.js`/`media-import.js` 的确认和原件流程。需要把语义适配到新编辑器事务，不能直接搬旧 DOM/CodeMirror 偏移实现后宣称兼容；本轮仅确认与记录，尚未接入。

目标入口沿用现有快捷记录窗口，正文内部换成通过验收的图文编辑器。保留标题/分类、新建与上下篇、主页面、自动保存、关闭退后台、默认可调五小时恢复、唤回默认中文和 4% 文字比例记忆。试验页的右侧预览只用于比对内容，正式快捷长文页不因此默认增加消息栏或 AI 栏；原 AI 栏按钮开关/默认隐藏需求继续有效。

1. 在隔离开发快捷窗口中先让测试新篇使用共享 richdoc 编辑器，接现有 render/commit/focus/selection/scroll 接口，体验按快捷长文流程验收。旧篇继续原 HTML/Markdown 编辑，不自动批量转换。
2. 同时做必要的最小保存适配：版本化富文档为正文权威，图片接媒体 ID/原件存储，串行提交与冲突检查；现有 HTML 可作安全阅读/搜索投影，不能形成另一份独立可改正文。当前 `validateEntry` 只接受 HTML/Markdown，不能直接把试验 JSON 塞进去宣称接入完成。最小适配接第二阶段模型，不等待朝花夕拾或云同步。
3. 在实际快捷窗逐项核对：新建分类/标题、中文唤回、手打时间戳、连续长文/插图、前后篇、自动保存失败留文、退后台/五小时内光标和滚动恢复、超时新篇、文字缩放/窗口记忆、主窗口打开同篇、备份导出恢复。再让主窗口和聊天呈现共用内容层；聊天归篇只读规则不变。

现有落点：`app/main.js` 装配 `createBodyEditor`；`editor/body-editor.js` 提供编辑器接口；`editor/persistence.js` 负责两种窗口共享保存队列；`features/quick-capture-window.js` 管理窗口焦点/导航；`shared/editor-document.js` 选择源格式；服务 `domain/entries.mjs` 校验现有正文格式。此表只说明已核对的接入位置，没有实现新接口或替换运行中的编辑器。
