# Android 本地完整存储与跨设备同步

2026-10-18 Android接入增量：手机0.11只用于UI手测；电脑/AVD0.12候选新增INTERNET与原生固定服务发现/status客户端，WebView联网拦截保留。只读目录快照不代替完整本地资料，未实现云同步/身份迁移/绑定或自动收件；最新后端仍按实际health能力与路由，不按package0.9.25猜已上线。见[接入与后续](ANDROID-SERVER-CONNECTION-012.md)及[实际验收](validation/2026-10-18-android-service-adaptation.md)，下方无联网权限等为先前0.11及更早阶段。


2026-10-18 同步接缝已新增：共用浏览器IDB outbox/inbox、独立原件/任务库及HTTP服务见[实际API](SYNC-BACKEND-IMPLEMENTATION.md)。它们已在隔离库验证，不等于Android SQLite/私有原件Repository已经接入。Android后续须在自身事务中保存内容+待发操作、原子应用收件+游标，完整保留Entry未知字段/分类/ID映射。安装包和用户手机本轮不动；网页联调没有离线静态壳，不能代替安装版本地冷启动。

2026-10-18用户明确确认：**文件和数据本身就在手机本地长期保存，云端只是同步服务**。此要求覆盖将Android理解成云API临时展示缓存的旧表述。本文是架构约束与适配准备；不宣称可靠同步/完整新存储已实施。

## 已确认行为

- 无网仍能打开会话/思绪、写日记、发本地消息、编辑分类和读取已存在媒体；本地存储不能依赖云端成功才能提交。
- 本地保存成功代表本机事务已提交，立即渲染；上传中/同步失败是另一种状态。不能因断网把本地保存标成失败，也不能把仅在内存的内容标成本地保存成功。
- 云端负责设备间交换增量/原件与协调版本，手机与电脑都保有自己的完整本地数据。退出应用、清理缓存、暂时离线不等于删除本地资料。
- 原图/GIF/视频等原件在本机私有资源目录，缩略图只是可重建显示缓存；消息、富文本和收藏引用稳定资源身份，不把blob URL/临时路径当跨端身份。

## 当前实现与差距

现在思绪使用SQLite schema3及私有media，随想使用独立TL IndexedDB与本地资源库；编辑RPC实际写本机，没有INTERNET权限。0.10共用richdoc/时间分段与保护式Entry adapter，0.11继续UI和恢复优化。这些是可保留的本地基础，**不是最终完整统一数据仓库或云同步已完成**。

当前LocalStore只能完整保存本地已支持Entry字段，完整桌面信封/独立附件/未知字段不能直接塞进后丢弃；旧格式/canonical权威要保留原件及正确写入口。未来适配必须补本地完整信封/业务对象的持久层，不能把这些对象长期只放远端，也不能为绕过能力保护裁剪原件。

TL对象作为前端显示适配，不作为跨设备业务协议；当前它仍是原型随想本地权威库，不能以“以后只是缓存”为由删除旧IDB。引入统一仓库时先做保留式身份/媒体/草稿迁移、失败恢复和双向样本验证，再明确切换权威，不能持续双写两套可编辑正文。

## 框架边界

| 部分             | 责任                                                                                                                         |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| UI/富文本适配器  | 从本地Repository读取、渲染和提交修改；不直接写云API，也不把Tiptap/气泡投影当另一份权威正文                                   |
| 本地Repository   | 完整Entry、规范消息/布局/引用、会话、分类、收藏和媒体元数据的版本化事务；原件/未知字段、草稿、删除标记和身份映射持久保留     |
| 同步outbox/inbox | 本地业务写入与待同步操作同一事务提交；稳定operationId/deviceId/基准远端revision；重开重试幂等，不用本地updatedAt猜同步游标   |
| 媒体适配         | 原件落盘、校验、稳定资源ID↔本地路径映射；上传回执和按需下载状态独立于正文位置/occurrenceId/insertedAt                        |
| 远端transport    | 鉴权、增量/媒体传输、重试/取消/能力发现；不拥有唯一数据副本，不改变本地保存成功的定义                                        |
| 冲突协调         | 本地修改版本与服务端revision分开，遇冲突保留双方原件/本地未同步输入，不静默覆盖。分类名称/顺序及聊天复合身份遵循电脑实际契约 |

本地编辑流程：输入→共用schema/算法→本地事务（业务对象＋outbox）→本地保存ACK/立即显示→后台同步→记录远端ACK。失败只更新同步状态并保留待发送操作；不能因重试重建entryId/unitId/blockId/messageId/occurrenceId。

远端接收流程：拉取/接收→校验能力、版本与资源身份→本地inbox幂等应用→增量通知UI；默认先展示本地已有数据，不能每次切页空白等待网络。

物理存储可以与电脑diary.json不同，业务对象/正文、时间算法和引用必须按[实际内容契约](DESKTOP-ANDROID-CONTENT-CONTRACT.md)一致。算法最终放本机还是云端的部署取舍仍可讨论，但这不改变“手机有完整可离线的数据”的已确认要求。

## 后续实施与验收

下一阶段按[数据统一计划](ANDROID-DATA-UNIFICATION-PLAN.md)、[同步设计](SYNC-V2-DESIGN.md)及后端会话2026-10-18新增的[调研](SYNC-ALGORITHM-RESEARCH-2026-10-18.md)/[协议草案](SYNC-PROTOCOL-DRAFT.md)细化实际Repository和迁移，先用合成库验证完整信封/身份/原件，再接受保护的同步服务。后两份仍是候选，不是现有端点；不按草案直接修改正式schema。没有现成远端接口时不制造假上传成功、假游标或仅内存outbox。

安卓适配按四个阶段推进：先完整信封/稳定ID和媒体原件的本地保留式迁移，再把受支持业务写口与outbox变成同事务，再实现inbox幂等应用和冲突保留，最后接远端transport。每阶段保留旧库/回执与恢复入口，能力未就绪继续用现有本地路径，不提前切换可编辑权威。

正常同步按变化游标/待确认队列增量处理，不每次扫描全库/hash所有文件。`localRevision`、远端对象版本、变化游标、内容时间及朝花夕拾运行游标分离；ACK只确认发送快照，不覆盖发送期间的新编辑。壁纸/头像/分类顺序等可移植配置也需版本化映射；设备DPI、临时路径和密钥不随之覆盖。朝花夕拾目标由服务器执行，安卓保存配置/绑定与可离线展示的投递，本地旧运行游标不能上传覆盖服务器进度。

必须包含：断网读写/重开、写入中强杀后的事务恢复、重复/乱序操作幂等、双方离线改同一条冲突、媒体未上传与下载失败、分类排序改名与未知字段、删除/撤回引用、旧IDB保留式迁移。同步服务不通过关闭现有桌面Host/Origin/访问锁实现。云服务未接入时继续明确显示本地模式。
