## 已确认模型

会话是消息容器，个人记录可切为群聊。人、程序、AI有各自参与者身份；消息包含发送者、会话、时间、内容及引用来源，程序不拥有整个会话。前端管理资料、渲染和提交参数，后台维护规则、运行进度、投递和来源关联。当前真实实现的provider只有朝花夕拾；AI的模型、提示词和调用逻辑仍后议。

后端新源码拆开固定房间/发送者假设：稳定会话身份来自已有journal sourceId与roomId；一会话可绑定多个独立实例；每个程序有稳定actor ID、参数、游标和历史归属。同会话多个窗口读取相同服务器状态，保存用revision校验。普通本人/程序发言进入同一canonical chat unit，引用程序历史则进入已有评论服务；解绑/换绑不能改属历史实例。客户端已出现并行ui43接线，本轮未验收，统一消息口能力仍未在日常API启用，不能把后端通过写成客户端已支持。

## 实施与验收边界

1. 后端原子设置口：创建/绑定/改参由原事务队列原子提交，失败无部分写入；相同参数重试不重复创建。纯开关暂停/恢复保留原checkpoint，规则改变沿原规则逻辑初始化新窗口，旧投递/评论不删。
2. 后端统一会话口：读取资料/参与者，按会话独立分页收件；人和已接入程序使用相同普通消息写口，支持Markdown文本/附件引用/普通回复/撤回；历史消息是只读来源投射，评论使用固定SourceRef，不复制旧正文。
3. 前端待接：固定白名单原生桥、worker按room/instance收件与保存ACK、来源/评论/撤回/草稿范围；单调度器管理各服务，异步切房不串路由，保留ui40待发ID筛选优化。详见新的后端接入契约，不执行tmp草稿。
4. 验证：8个新集成场景与相邻场景共68项已分阶段通过；首次Windows文件替换失败及补充发现的实例归档编号前缀校验问题都保留记录，最终边界见validation。没有正式启用或UI验收。

当前候选provider包括内置revisit与external-program。后者实际提供外部程序/AI角色的参数和消息读写通道，不提供执行器；日常旧API仍仅revisit。AI执行器/独立外部机器人账号与权限尚未实现。actorId表示已登录库所有者授权下的发送者归属，不是机器人的独立登录凭据。现有同步产品库与本机日常库仍为两个接缝，新增会话能力不等同已经迁云/安卓互通。
