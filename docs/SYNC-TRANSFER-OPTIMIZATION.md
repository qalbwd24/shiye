# 同步传输优化与手机自动初始化

2026-10-18用户新增确认：正式同步只走统一新版结构；Android接好后先少量数据往返；云端首次资料可由电脑发送数据包、服务器AI执行固定脚本解包接入。手机不应承担手动解压、分类、安装壁纸文件等步骤，全部由Repository/资源任务自动完成。云端计划见[种子与迁移](SERVER-SEED-AND-MIGRATION-PLAN.md)。

## 现场事实

- 正式dataDir容量约3.33GB，其中1.46GB为保留的导入原包；当前兼容适配器的正文结构+现有媒体估算约1.85GB。严格新版导出后的真实大小以新manifest重算，不能把此数当未来固定包大小。[只读容量记录](STORAGE-AND-ANDROID-IMPORT-2026-10-18.md)
- 本轮`tailscale ping --c 4 --timeout 3s`对FlClash内嵌手机节点取得1次直接连接回应、约30ms；达到直连后命令提前结束，不能写成4次全部完成。证据`outputs/sync-network-assessment/probe.json`，原始输出仅`tmp/sync-network-assessment/`。
- 空闲status中Relay=hkg不代表当前流量正在香港中继；本轮主动ping已直连。没有跑整库吞吐、手机APK或持续连接实测，没有改VPN/代理/防火墙/MTU。
- Tailscale直连通常比DERP中继吞吐更高，DERP有公平吞吐限制；见官方[连接类型](https://tailscale.com/docs/reference/connection-types)和[性能排错](https://tailscale.com/docs/reference/troubleshooting/poor-performance-tailnet)。当前无需仅因总资料GB级就重做VPN。

## 当前实现与缺口

| 项目        | 已有事实                                            | 后续接线/优化                                                                          |
| ----------- | --------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 实体增量    | sync-v2序号/回执/游标，只交换变更实体               | Android实际Repository及电脑日常保存登记继续接入                                        |
| 上传断点    | 服务端持久缺块、SHA、原件复用；默认256KiB/块        | Android保持任务/身份，失败续传而非重新生成assetId                                      |
| 下载        | 后端授权Range、共享下载器分段拉取                   | 共用JS下载器仍分配整件内存，缓存队列只在整件完成时落盘；不能说已有跨强杀的下载分块断点 |
| 媒体调度    | 现有缓存transfer按任务串行处理                      | 文字/设置优先，媒体有限并发、前后台限速及可恢复下载文件层待接                          |
| 主题/壁纸等 | 产品configuration/appearance及media/sticker对象可传 | 各端现有IDB/私有文件需明确映射并登记，后台不会自动收集所有散落文件                     |

1.85GB是全部待补媒体的总量，不是单个HTTP请求或内存缓冲。现有512MiB限制为**单件资源**上限；本次统计最大现存媒体约237.8MB，不能误解为整个资料库最多512MiB。

## 确认的手机体验

手机只需连接、配对、启用相应同步范围；应用在后台读取结构记录、自动保存本地索引/正文/任务，并按资源ID下载，不要求用户手动搬运和解压媒体。

资源传输与展示分开，按用户最新[共享范围](SYNC-DATA-SCOPES.md)，以会话识别图为例：

```text
会话识别图：稳定assetId（具体映射适配旧会话字段）
媒体索引：assetId → sha256 / MIME / size
资源任务：缺少原件 → 授权分块下载 → 私有文件 → 校验
安卓展示：会话头像可引用该图；聊天壁纸仍由安卓本机单独设置
```

图片/视频/GIF/头像都用同一资源机制；分类/标签及顺序、会话名称/归属、表情包名称/备注/分组是共同业务数据。导入素材不自动覆盖本机壁纸和铺图参数。图片字节仍须实际传到手机，单发JSON编号不能凭空生成图片。不在JSON反复塞入base64大图，也不把电脑路径或Blob URL当跨端引用。

推荐接收优先级（开发方案，尚未全部实现）：

1. 库身份、分类/会话配置和正文结构先持久落地，尽早可读写；外置大正文先保存待取任务，不以空正文覆盖。
2. 当前会话头像、当前查看附件和必要小预览优先；若本机主动选用了远端资源作壁纸再提高其优先级。下载完成前显示稳定占位/已有外观，不闪换草稿或布局。
3. 其它图片/GIF/视频原件后台继续下载，逐步形成用户要求的完整离线副本。仅按需读取不能冒充全量离线完成。
4. 新消息/设置同步始终有资源预算；媒体可先评估2个并发任务，再通过吞吐、内存和输入响应实测决定是否增加，不无限并发。
5. 提供总进度/剩余字节、暂停/恢复、流量策略；从断点恢复，不要求一次保持连接直到所有文件结束。

## 下载断点实现要求

Android采用私有文件`.part`与同Repository的device-local transfer任务，记录libraryId/epoch、assetId、预期hash/size、已验证范围、状态/重试依据。分段写盘并持久记录已确认范围；崩溃恢复核对文件和范围，不能只信文件长度。完成后整件校验、原子发布最终文件、事务更新可用状态；失败保留可恢复任务，UI不假报完成。任务中的私有路径不进入跨端业务信封。

共享JS下载器的整件Uint8Array仅可作为隔离/小文件实现依据，不能照搬为几百MB媒体的手机持久方案。上传块大小改变仅对新任务协商，已开始任务沿原chunkSize恢复。块大小、并发和背压都要按真实包测量，不从30ms探测推算具体MB/s或宣称已提速。

## 云端与后续验证

电脑可先把新版结构包/媒体原件上传云端，云端校验导入后成为数据来源；手机仍经同一API初始化，不需要接触这个压缩包。未来Tailscale/HTTPS均可作为受信入口，迁移保持库身份/版本/回执后再换地址。

先等待Android接线，用合成小批次验证文字、分类改名、会话壁纸/头像、图片/GIF/视频、引用、撤回、断线续传、进度及重开；随后取少量经新版转换核对的真实资料，再考虑整库。测试不操作日常旧库或其它会话正在使用的窗口。
