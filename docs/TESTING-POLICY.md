# 按影响范围选择验证

2026-10-17 用户明确：小改不应消耗大量时间和资源重复无关检查，应重点验证最核心变化的场景。本文件覆盖此前“一律整套检查”的习惯。

先说明改了什么、可能影响什么，选择能发现真实回归的最少场景。复用未改路径的既有证据，记录对应源码或程序哈希；不要把旧包通过写成新包完整通过。

| 改动                           | 默认验证                                                                  |
| ------------------------------ | ------------------------------------------------------------------------- |
| 文案、局部间距/颜色            | 受影响页面实际查看，必要的窄宽/字号边界；不跑全项目测试                   |
| 输入、滚动、动画               | 原问题复现与修复对照、核心快速操作、相邻模式；实际帧优先，避免重复大矩阵  |
| 消息排序/确认                  | 同秒/跨秒、确认乱序与快速连发定向测试；当前包关键真实发送验证             |
| 维护脚本                       | 正常/失败路径与只读约束的合成测试、实际状态回读；不为测试反复升级正式程序 |
| 共享底层、存储/恢复、依赖/构建 | 根据受影响调用方扩大检查；数据兼容和恢复必须有专门样本，必要时完整check   |

定向失败应先定位原因，再添加能覆盖该原因的场景，不自动重跑所有旧检查。只有修改影响了此前证据、环境改变使结果失效，或仍存在明确风险才重测。正确性检查可适度并行，动画时间与长帧采样应单独运行；不把rAF频率当作物理120FPS。

交付报告简要写实际通过的核心场景、复用证据和未验边界。常规升级仍核对保存状态、进程归属，保存快照，检查候选与安装文件哈希及运行版本。无需每次重复与本次改动无关的完整原生/浏览器通测。

本轮ui22按最新要求停止继续扩展旧动画模式矩阵，保留已完成结果；剩余原生聚焦输入框起点单发、平滑自动多行连发、即时自动多行连发。旧645＋10原生结果只作明确标注的基线，不冒充新排序包完整验收。
