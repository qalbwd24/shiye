# 0.7 工作计划与交接

## 用户需求与实施顺序

1. 先恢复最新日记中错误替换的图片引用，核对原文件、时间、正文及历史。
2. 分清日记标识冲突、同名文件、相同内容去重；所有替换明确作用范围，保留原件。
3. 分类、标签和图片共用拖动排序；内部拖动不再触发上传或往正文插入图片。
4. 图片完整比例展示，提供居中大图；图文区可切换左右及上下位置、调节宽度。
5. 日记图片下增加自己的本地评论，支持编辑、移除、恢复，进入加密备份。
6. 独立折叠导航／列表／媒体栏，统一设置入口，居中弹窗，控制基础界面复杂度。
7. 隔离库自动测试和浏览器验收完成后启动正式新版，核对版本并记录数据快照。

## 子 agent 分工与边界

本轮三个 Astra 子 agent 分别负责数据冲突、拖动图库、工作台界面。共享独立工作树，按文件分配所有权；根 agent 负责数据恢复、评论、接线、集成验证和发布。

| 功能         | 前端                                      | 后端／共享                                             | 维护重点                                      |
| ------------ | ----------------------------------------- | ------------------------------------------------------ | --------------------------------------------- |
| 图库与排序   | features/gallery.js                       | core/drag-sort.js                                      | 只改变附件 ID 顺序，不上传、不改媒体字节      |
| 文件导入反馈 | features/media-import.js、core/api.js     | routes/media.mjs                                       | 外部 Files 与内部拖动分离，记录源修改时间     |
| 分类标签     | features/organization.js                  | routes/taxonomy.mjs                                    | 手动／名称等排序可选，通用拖动与键盘操作      |
| 冲突核对     | features/conflicts.js                     | domain/import-reconciliation.mjs、routes/conflicts.mjs | 标识不等于文件名；范围、版本检查、历史与撤销  |
| 本地评论     | features/comments.js、styles/comments.css | routes/comments.mjs                                    | 评论独立于 HTML，软删除，日记和评论双版本检查 |
| 工作台       | features/workbench.js、layout.js          | shared/appearance.js、preferences.layout               | 复用原设置节点及事件，独立折叠、图文位置      |

入口在 public/features/index.js 和 src/server/app.mjs。main.js 只调度当前日记和渲染；不重新实现上述功能。

## 数据恢复记录

0.6 旧媒体冲突操作曾把多篇日记的附件引用全局替换，并去重引用，造成最新日记的 3 张原图不显示。原文件未删除。已在带 revision 校验的本地 API 中补回这 3 个 ID，保留当前其他附件及正文，共 6 个附件。修复前完整快照与核对结果在核心目录的 `迁移记录/修复图片引用-2026-09-14T13-23-08-281Z`，不进入源码包。

历史中更早的全局操作可能影响其他日记，不能凭文件名反向批量替换。需要按历史逐篇核对；本轮确定性恢复只针对用户报告的最新一篇。

## 维护边界

- 本轮没有改变加密协议、官方账号或云服务器；本地评论随现有加密全备份保存。
- 本地评论不加入正文字符统计或普通文本导出。评论删除可在原位置恢复；整篇日记的旧正文恢复不自动回滚评论。
- 图片原始拍摄时间在 EXIF 中时，原字节保持不变；源文件修改时间与导入时间分开记录。以前未记录的源时间不编造。磁盘复制产生的创建时间不等于拍摄时间。
- 不宣称已完整复刻 Android 所有功能；以 FEATURE-PARITY.md 的已实现／待核对清单为准。

## 操作简表

分类管理中的拖动柄可拖动排序，也可使用排序按钮或 Alt＋方向键。图片在媒体区同样操作，单独的查看按钮打开完整大图；双击进入原有图片编辑副本功能。设置 → 布局可选择媒体左右／底部位置和宽度；顶部导航、列表、媒体按钮独立折叠。评论写在图片下方，点击评论保存；点击回复生成引用摘要，回复可展开／折叠。

验收与实际运行版本见 validation/0.7-validation.md；下一轮优先处理用户真实使用反馈，不扩大到未验证的云同步。

## 本轮追加需求及结果

阅读模式一次展示一个附件，上下切换；正文/标题聚焦或点击进入写作按钮时进入专业写作，图片改为缩略图排序。返回阅读不会覆盖已保存的布局。

评论位于图片下方，创建时保存头像/用户名/时间快照，回复保存被回复内容摘要且可折叠，支持照片/GIF小裁切图，点击查看完整原图，另有常用Unicode表情。表情包收藏、分组、搜索、删除恢复和评论选择面板已实现；GIF保留动画原件，动画专用压缩留作后续模块。

所有新日记附件先经批量勾选窗口，可取消／全选并选原件、均衡、清晰。图片压缩沿用原版“小图与GIF跳过”的思路，具体参数与安全界限见MEDIA-COMPRESSION.md和MEDIA-COMPRESSION-REFERENCE.md。视频没有找到原版转码依据，本版使用已有FFmpeg新增可选压缩，不宣称复刻原实现。

Bilibili图文创作小助手公开说明提供了评论缩略图、查看大图、多图展开的直接参考：https://www.bilibili.com/opus/752428294212681795 。本版借鉴头像列、昵称/时间层级、引用块、回复折叠与评论小图布局，不复制平台资源。小红书公开网页在本次访问中超时，未把未见的页面细节描述成已验证；单图+图文分区按用户要求实现。后续进一步视觉优化应补充用户可访问的网页核对。

## 个人资料与最终上传语义

左上角显示头像、用户名和座右铭内容。点击该区域或设置→个人资料编辑。支持GIF动画头像；拖动圆形预览或调节位置/缩放是显示裁剪，不修改动画文件。共享shared/profile.js负责裁剪校验与显示，评论快照使用相同规则。参考Radix Avatar和react-easy-crop的头像容器、拖动缩放交互：
https://www.radix-ui.com/primitives/docs/components/avatar
https://github.com/ValentinH/react-easy-crop

批量导入最终语义：默认添加所有文件并压缩；勾选“保留原件”才跳过压缩。不需要添加的文件点“不添加”，可恢复。均衡/清晰只控制未勾选文件。普通GIF/APNG/动画WebP自动保留，不会静态化。

表情包入口：设置→表情包；支持本地导入、已有图片收藏、搜索/分组、改名、删除恢复。评论里的“表情包”只加入草稿，仍须点击评论才保存。收藏与历史评论媒体分开引用，同一图片按内容复用，不复制成第二份媒体。头像、座右铭、表情包的后端分别为preferences/profile、stickers模块。
