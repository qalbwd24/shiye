# 拾页真机调试

已安装官方 scrcpy 5.0.1，USB固定连接这台荣耀手机；ADB沿用项目现有版本。配置为 `tools/android-device-debug.json`，不会更改系统PATH或重启ADB服务。

后续开发会话会在需要真机复测时提醒使用。你通常只需连USB、解锁并打开样机，再告诉会话哪里有问题；连接检查、WebView重连及问题定位由会话负责，下面的入口也可自行使用。

1. 手机先打开「拾页 · 样机」。
2. 双击「手机投屏.cmd」：用鼠标/键盘操作投屏。只观察时使用「只读投屏.cmd」。关闭投屏窗口即停止。默认不录音、不录屏、不自动同步剪贴板，也不改变手机休眠或旋转设置。
3. 双击「WebView调试.cmd」。它只连接 `dev.shiye.visualqa` 当前进程，自动打开本地调试入口页，点击「Inspect WebView」进入官方DevTools（前端资源需联网）。入口不显示日记/会话标题。
4. 也可在Chrome打开 `chrome://inspect/#devices`（Edge为 `edge://inspect/#devices`）。开启 Discover network targets，在 Configure 中添加命令输出的 `127.0.0.1:端口`，然后点对应网页的 inspect。USB设备发现已启用时也可能直接列出目标。
5. App重启后再次运行「WebView调试.cmd」，再更新浏览器端口；工具会只清理自己的旧映射。结束后可双击「关闭WebView连接.cmd」。

配置脚本也可直接执行：`powershell -NoProfile -ExecutionPolicy Bypass -File tools/android-device-debug.ps1 -Action Status`，Action另可选Mirror、WebView、StopWebView。

后续调试优先在样机和生成测试资料中进行。此入口不安装APK、不启动手机App、不清库、不操作其他App；产品修复仍按对应任务执行。scrcpy投屏上限设60fps用于观察，不代表手机120Hz验收；精细性能需配合ADB帧耗时/轨迹分析，采集范围按具体测试确定。

WebView调试已在项目的debug包启用。DevTools中临时CSS调整可立即预览，但刷新可能丢失；正式改动须写回对应准确源码/私有stage并构包。原生Android控件不在DOM中，使用ADB/原生诊断检查。
